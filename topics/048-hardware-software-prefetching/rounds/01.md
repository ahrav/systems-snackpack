# Round 1: test explicit read prefetch on an irregular gather

## Question

Does one low-locality software read hint improve steady-state elapsed time for
a scalar randomized-index gather on each required Linux host? How does the
answer change across source distances 4, 8, 16, 32, and 64?

The experiment tests correctness, steady-state elapsed time, and linked code
generation. It does not measure hardware-prefetch activity, cache-serving
level, memory latency, translation cost, request-buffer occupancy, or memory
bandwidth.

## Frozen comparison

- Source: one sealed Git archive from the first Topic 48 source commit.
- Build: GNU Compiler Collection (GCC) 11.5 with `-O3 -g -std=c11 -Wall -Wextra -Werror
  -march=native -fno-tree-vectorize -fno-tree-slp-vectorize`.
- Work: 4,194,304 records of 64 bytes, or 256 mebibytes (MiB), and a deterministic
  Fisher-Yates permutation that visits every record once per pass.
- State: one untimed demand-only warmup pass followed by two timed passes.
- Placement: one fresh process pinned to logical CPU 0. Initialization first
  touches the allocation after pinning.
- Primary treatment: demand-only scalar gather versus the same gather with
  `__builtin_prefetch(&lines[order[i + distance]], 0, 0)`.
- Distances: 4, 8, 16, 32, and 64, visited in one recorded seed-shuffled order.
- Replication: four complete ABBA/BAAB blocks per distance. Each letter is a
  fresh process. One complete four-process block is one replication.
- Controls: two A/A blocks route demand-only through both labels. A separate
  two-block sequential case at distance 16 checks a regular stream.
- Stopping: seeds, distances, block counts, inputs, and commands are fixed
  before final collection. Failed attempts remain in the receipt.

## Analysis

Within each complete block, average the natural-log time per access for B and
subtract the corresponding A average. Exponentiate the mean block contrast to
obtain the geometric-mean B/A ratio. Report block count, sample dispersion,
range, and the predeclared two-sided 95% Student-t interval over block log
contrasts.

The interval describes process-to-process and temporal variation during one
exact host, binary, workload, and run window. It does not cover other builds,
processors, permutations, or machines. Distance comparisons remain exploratory
because one shuffled distance order does not isolate a response curve.

## Acceptance contract

1. The source archive embeds the recorded commit and matches its Secure Hash
   Algorithm 256-bit (SHA-256) digest.
2. The literal Arm host reports AArch64. The `xxl` alias is resolved during the
   run, and its backing host reports x86-64.
3. Host records include `uname`, central processing unit (CPU) model, kernel,
   compiler, native target and tuning, available CPU count, line size, and CPU
   0 topology.
4. The source, runner, analyzer, validator, archive, and binary SHA-256 digests
   remain unchanged throughout collection.
5. Every process checks its sum, input echo, process identifier (PID), CPU
   placement, timed page faults, and accepted `MADV_NOHUGEPAGE` requests. That
   Linux advice asks not to use automatically managed transparent huge pages;
   acceptance does not prove the eventual page size.
6. All attempts remain in chronological order. No failed process is replaced or
   silently retried.
7. Each primary block contains exactly two A and two B runs with the declared
   template. A/A sends byte-identical demand work through both labels.
8. Linked `kernel_demand` and `kernel_prefetch` symbols remain inspectable, and
   the exact emitted hint is recorded for each host.
9. The analyzer and independent validator agree on every retained summary.
10. Timing, correctness, code generation, host identity, and mechanism
    inferences remain separate.

## Controls

- Keep source, compiler flags, binary digest, permutation seed, data size,
  passes, page advice, affinity, and warmup fixed.
- Keep allocation and initialization, warmup, steady timing, and teardown
  separate.
- Record every checksum failure, fault, migration, timeout, and nonzero exit.
- Treat a complete process block as the analysis unit. Loop accesses and passes
  are subsamples.
- Inspect the exact linked binary rather than inferring code generation from
  source or compiler flags.
- Use the distance sweep only to explore. Confirm any selected distance with a
  fresh fixed comparison.
- Leave hardware prefetch controls in their production state. A privileged
  control experiment requires a separate snapshot, restore, and verification
  plan.

## Evidence boundary

Elapsed time can establish an exact-workload difference. Disassembly can
establish which hint instruction GCC retained. Neither fact attributes an
effect to hardware-prefetch redundancy, cache pollution, bandwidth, translation,
or request pressure. Those mechanisms require direct, model-specific evidence.

Final observations and receipt hashes are added only after both required hosts
pass this contract using the exact checked-in source candidate.

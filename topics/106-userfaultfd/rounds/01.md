Each host runs the full Cartesian product of 1/17/256 pages, 1/4 writers,
1/8 full-page write passes, and three schedules. Pre-copy produces zero events.
Fault-only copies every page through the handler. Racing schedules preserve
bytes while dividing work between handler and scanner. For 256 pages, the
handler copied 71..114 pages on Arm and 75..122 on x86 across the four racing
configurations. These counts describe these schedules; the configurations
have different writer and pass counts and are not repeated timing trials.

The Python oracle builds the epoch image directly from page/byte coordinates,
then separately derives the live image after the declared number of passes.
It compares entire files. The Rust oracle eagerly clones the initial image
before enumerating seven operations from six choices, including repeated saves
and writes. Two unit tests and one doctest pass on all three hosts.

Scope: fixed populated private anonymous mappings, disjoint page ownership
among writers, one epoch, all writes through the registered mapping, atomic
bytes, no kernel/device writes, and preallocated handler metadata. This checks
snapshot bytes and operation counts. Writer latency, throughput, production
transaction consistency, crash recovery, and arbitrary mapping changes remain
unmeasured. No performance winner is claimed.

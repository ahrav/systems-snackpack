## Fixed process-block results

The primary treatment changes access order and advisory policy together.
Treatment A scans sequentially with `POSIX_FADV_SEQUENTIAL`. Treatment B uses
a deterministic shuffled order with `POSIX_FADV_RANDOM`.

| Process observation | Sequential buffered | Randomized buffered |
|---|---:|---:|
| Fresh process count | 16 | 16 |
| Median measured scan | 48.505881 ms | 2,343.360340 ms |
| Median startup to measured scan | 1.325354 ms | 0.507171 ms |

Across eight complete four-process blocks, randomized buffered time divided by
sequential buffered time was `48.435894`. The two-sided 95% interval based on
Student's t-distribution was `[47.604306, 49.282010]`. The construction uses the variation among the eight
complete block ratios to account for the small block count. The interval
covers variation among those eight blocks on this host and run window. It
excludes host, kernel, build, filesystem, and device-population variation.

The same-treatment A/A control ran the sequential buffered method under two
labels. Each label used 16 fresh processes. The Y/X ratio was `0.996291`, with interval
`[0.989118, 1.003517]`. Median scan times were 48.802588 and 48.724325 ms.
A/A checks the two mechanical paths. It is not a noise floor.

The direct-I/O comparison used four complete blocks and eight fresh processes
per method:

| Process observation | Sequential buffered | Sequential direct |
|---|---:|---:|
| Median measured scan | 48.413702 ms | 2,338.591319 ms |
| Median startup to measured scan | 0.137084 ms | 0.418285 ms |

Direct time divided by buffered time was `48.168147`, with interval
`[46.907396, 49.462783]`. This result covers serialized 4 KiB reads of one
16 MiB file. It does not establish a general direct-I/O penalty.

All 80 campaign rows used distinct process identifiers and passed block
identity-sentinel, byte-count, source, schedule, and cold-page-cache checks.
Every timed process started with zero resident pages and reported 16,777,216
physical read bytes.
All eight direct processes opened with `O_DIRECT`. `statx` reported 4-byte
memory and 512-byte offset alignment. The allocator used a pointer-safe 8-byte
alignment, and every 4 KiB request met both reported constraints. All eight
accepted direct processes reported zero resident pages afterward. The harness
records post-direct residency as telemetry because `O_DIRECT` tries to
minimize cache effects but does not make zero residency an application binary
interface promise.

## Semantic and writeback controls

After verified zero residency, one 4 KiB sequential-advice read left 12 pages
resident after 20 ms and added 49,152 physical read bytes. The random-advice
control left one page resident and added 4,096 physical read bytes. Each result
came from one control process, not a repeated timing campaign.

The 4 MiB buffered-write control reported a 3.961262 ms fill-and-write-loop
interval and a 2.710824 ms interval from the end of that loop through
`fdatasync` returning. The latter also includes the intervening
`/proc/self/io`, `mincore`, and `/proc/vmstat` samples, so it is not isolated
`fdatasync` latency. All 1,024 pages were resident after the write loop and
remained resident after `fdatasync`; `POSIX_FADV_DONTNEED` then reduced the
count to zero. The process reported 4 MiB of logical and process-accounted
write bytes before the sync and no additional process-accounted write bytes
across the subsequent sampling-and-sync interval. That accounting does not
prove that the sync caused no device or filesystem work. Host-global dirty
pages changed from 4,352 to 5,360 and back to 4,352. Other processes can change
those counters.

## Linked-code observation

The x86-64 binary retains `verify_block` as a separate symbol. Its linked code
loads and checks the first and last eight-byte identity sentinels of each 4 KiB
block, uses `imul` and `xor` to update the checksum and expected markers, and
uses `cmp` with conditional control flow to return the result. The linked
disassembly contains calls to
`pread`, `posix_fadvise`, `mincore`, and `fdatasync`. This confirms that the
scan still performs each read and checks its two identity sentinels. It does
not attribute the timing ratio to x86 instruction behavior.

## Measured and inferred

Measured: elapsed read-loop time, startup time, per-process read accounting,
page residency, block identity sentinels, direct-I/O alignment, the
fill-and-write-loop interval, the write-end-to-`fdatasync`-return interval,
host metadata, source and binary identity, and linked code.

Inferred: the 48-fold randomized slowdown is consistent with losing sequential
read-ahead and request locality while issuing serialized 4 KiB reads. The
experiment changes order and advice together and lacks block request or device
service traces, so it does not identify one kernel or device mechanism.

## Fixed process-block results

The primary treatment changes both the access order and the advisory policy.
Treatment A scans sequentially with `POSIX_FADV_SEQUENTIAL`. Treatment B uses
a deterministic shuffled order with `POSIX_FADV_RANDOM`. The ratio therefore
does not isolate either change by itself.

| Process observation | Sequential buffered | Randomized buffered |
|---|---:|---:|
| Fresh process count | 16 | 16 |
| Median measured scan | 48.464361 ms | 2,342.362265 ms |
| Median startup to measured scan | 1.684260 ms | 0.965182 ms |

Across eight complete four-process blocks, randomized buffered time divided by
sequential buffered time was `47.975044`. The two-sided 95% interval based on
Student's t-distribution was `[47.538366, 48.415734]`. The construction uses
the variation among the eight complete block ratios to account for the small
block count. The interval covers variation among those eight blocks on this
host and run window. It excludes host, kernel, build, filesystem, and
device-population variation.

The same-treatment A/A control ran the sequential buffered method under two
labels. Each label used 16 fresh processes. The Y/X ratio was `0.999580`, with interval
`[0.986196, 1.013145]`. Median scan times were 49.897427 and 49.627102 ms.
A/A checks the two mechanical paths. It is not a noise floor.

The direct-I/O comparison used four complete blocks and eight fresh processes
per method:

| Process observation | Sequential buffered | Sequential direct |
|---|---:|---:|
| Median measured scan | 48.980570 ms | 2,339.839913 ms |
| Median startup to measured scan | 0.137487 ms | 0.668349 ms |

Direct time divided by buffered time was `47.688376`, with interval
`[46.419597, 48.991834]`. This result covers serialized 4 KiB reads of one
16 MiB file. It does not establish a general direct-I/O penalty.

All 80 campaign rows used distinct process identifiers and passed block
identity-sentinel, byte-count, source, schedule, and cold-page-cache checks.
Every timed process started with zero resident pages and reported 16,777,216
physical read bytes.
All eight direct processes opened with `O_DIRECT`. `statx` reported 4-byte
memory and 512-byte offset alignment. The allocator used a pointer-safe 8-byte
alignment, and every fixed 4 KiB request met both reported constraints. All
eight direct processes happened to report zero resident pages afterward. That
last value is telemetry, not part of the direct-I/O validity rule.

## Semantic and writeback controls

After verified zero residency, one 4 KiB sequential-advice read left 12 pages
resident after 20 ms and added 49,152 physical read bytes. The random-advice
control left one page resident and added 4,096 physical read bytes. Each was
one control process, so the result demonstrates the available host behavior
without estimating its frequency.

The 4 MiB buffered-write control reported a 5.001820 ms fill-and-write-loop
interval and a 5.633615 ms interval from the end of that loop through
`fdatasync` returning. The latter also includes the intervening
`/proc/self/io`, `mincore`, and `/proc/vmstat` samples, so it is not isolated
`fdatasync` latency. All 1,024 file pages were resident after the write loop
and remained resident after `fdatasync`; `POSIX_FADV_DONTNEED` then reduced the
count to zero. The process reported 4 MiB of logical and process-accounted
write bytes before the sync and no additional process-accounted write bytes
across the subsequent sampling-and-sync interval. That accounting does not
mean `fdatasync` performed no work. Host-global dirty pages changed from 1,340
to 2,348 and back to 1,340. Other processes can change those global counters.

## Linked-code observation

The AArch64 binary retains `verify_block` as a separate symbol. Its linked code
loads and checks the first and last eight-byte identity sentinels of each 4 KiB
block, uses `mul` and `eor` to update the checksum and expected markers, and
uses `cmp` plus conditional control flow to return the verification result.
The linked disassembly contains calls to `pread`, `posix_fadvise`, `mincore`,
and `fdatasync`. This confirms that the measured scan still performs each read
and checks its two identity
sentinels. It does not attribute the timing ratio to instruction throughput.

## Measured and inferred

Measured: elapsed read-loop time, startup time, per-process read accounting,
page residency, block identity sentinels, direct-I/O alignment, the
fill-and-write-loop interval, the write-end-to-`fdatasync`-return interval,
host metadata, source and binary identity, and linked code.

Inferred: the 48-fold randomized slowdown is consistent with losing sequential
read-ahead and request locality while issuing serialized 4 KiB reads. The
experiment changes order and advice together and does not trace block request
merging, queue occupancy, or device service time, so it cannot assign a unique
kernel or device cause.

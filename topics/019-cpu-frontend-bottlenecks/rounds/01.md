# Round 1: final layout controls frontend demand

## Decision rule

Diagnose the pipeline before changing layout:

1. Define one CPU-bound phase and separate startup from steady state.
2. Use the exact processor's supported top-level metrics.
3. Separate frontend latency from frontend bandwidth where the PMU permits it.
4. Inspect redirects, L1I, instruction-TLB, cached-operation, and decoder
   evidence independently.
5. Match samples to the loaded binary and inspect its final addresses.
6. Apply one output-preserving layout treatment.
7. Rerun correctness, paired process timing, code inspection, and credible
   counters.

Require movement in runtime and final layout before claiming a layout effect.
Require a mechanism-specific observation before naming the mechanism.

## Cost model

For supply source \(s\), let \(U_s\) denote delivered operations and \(B_s\)
denote sustainable operations per cycle. Let \(C_{switch}\) denote supply-path
transition cycles. For instruction-cache misses, translation misses, and
redirects, let \(M_x\) denote event count and \(L_x^e\) denote exposed,
non-overlapped cycles per event.

\[
C_{FE} \gtrsim
\sum_s \frac{U_s}{B_s}
+ C_{switch}
+ M_I L_I^e
+ M_T L_T^e
+ M_R L_R^e.
\]

For a CPU-bound phase:

\[
C_{phase} \gtrsim \max(C_{FE}, C_{BE}).
\]

This accounting model is not a cycle simulator. Raw event latency does not
equal exposed latency. Fetch, translation, decode, wrong-path work, and backend
execution overlap. Adding raw handbook latencies double-counts hidden work.

## Cold outlining has a workload-dependent break-even point

Let \(H\) and \(C\) denote hot-path and cold-path executions. Let \(\Delta h\)
denote frontend cycles removed from one hot execution. Let \(k_c\) denote cycles
added to one cold execution by calls, branches, refills, and lost optimization.
Outline when:

\[
H\Delta h > Ck_c.
\]

Equality is break-even. A source-level `#[cold]` attribute supplies a hint; only
the final linked layout establishes whether the treatment moved code.

## Failure modes

- Low instructions per cycle can come from backend stalls or speculation.
- L1I misses do not prove decoded-operation-cache pressure.
- L1I hits do not prove adequate decode bandwidth.
- Broad alignment can repair one boundary and enlarge the active code footprint.
- Inlining and unrolling can improve one loop while displacing other hot code.
- Large executable pages increase translation reach, not L1I capacity.
- Virtual machines can omit, synthesize, or reject PMU events.
- Counter multiplexing can give different events different phase coverage.
- A single process provides subsamples, not independent replication.
- One processor result does not establish an ISA-wide effect.

## Evidence contract

Pair and order-balance fresh processes for performance comparisons. Report the
process count, point estimate, and an interval or dispersion measure. State
whether timing includes startup. Retain raw rows and final-image code
inspection.

Classify evidence explicitly:

- **Measured:** elapsed time, event counts and running fractions, section sizes,
  symbol addresses, and final instructions.
- **Observed vendor evidence:** CPU model identifiers and official
  implementation documentation.
- **Inferred:** the share caused by instruction cache, translation, decoded
  operations, branch targets, prediction, or prefetching.

## Focused experiment

The checked-in generator emits 512 equal leaf functions. The treatment requests
16-byte or 4096-byte alignment while holding source, compiler options, call
order, call count, and checksum constant. Final ELF inspection must establish
the requested spacing and equal leaf code size before timing is interpreted.

The primary estimand is the steady-state
`sparse4096/dense16` nanoseconds-per-call ratio. Twelve order-balanced process
blocks provide the independent analysis units. A hard-linked dense/dense A/A
run exercises the same launch and analysis path. Separate order-balanced PMU
passes retain running fractions and unsupported events, but do not replace the
timing estimand or establish causality.

The 4096-byte request is a spacing treatment, not an assertion that every
system uses 4096-byte pages. Record the host page size. Even when it is 4096,
the treatment jointly changes instruction-cache, instruction-translation,
branch-target, and prefetch conditions.

# Reader-writer lock collapse

Concurrent readers can still modify one shared lock-state word. A queued writer
can also prevent later readers from entering. Read percentage alone does not
predict throughput or tail latency. The Rust API leaves admission policy
unspecified; the model here explicitly chooses one of two simplified policies.

The routing record is `(generation, destination)`, with destination equal to
100 times generation modulo 2^64. One read must see a whole version. Work may
finish using that version after a newer version is published. This permits
copying the 16-byte record and releasing the read guard before computation.

Three timed candidates use identical request work: `mutex` and `rwlock` retain
the guard through computation; `snapshot` copies under a read guard and releases
before computation. Timed runs have no writers. Concurrent updates are exercised
separately by correctness tests. Do not interpret this probe as writer-tail
latency, open-loop service behavior, or an immutable-publication benchmark.

```bash
cargo test -p reader-writer-collapse
cargo run --release -p reader-writer-collapse -- bench rwlock 4 250000 0
python3 topics/083-reader-writer-collapse/experiment/oracle.py target/release/reader-writer-collapse
cd topics/083-reader-writer-collapse
rustup run 1.93.1 python3 experiment/run.py /tmp/topic083-new-output-directory
```

The runner uses Rust 1.93.1 and refuses an existing output directory. On Linux it
selects and verifies per-worker affinity on eight distinct visible cores in one
NUMA node. Other systems record uncontrolled placement. Output CSV has mode,
worker count, operations per worker, arithmetic rounds, elapsed nanoseconds, and
checksum. Identical workloads must have identical checksums across candidates.

Six unit tests and one doctest cover guard lifetime, whole versions under updates,
model boundaries, and equivalent candidate computations. The Python oracle checks
3,420 schedules by advancing logical time and 48 computations with independent
integer arithmetic. No source code is generated by the oracle.

Selection: begin with a mutex for simple small operations; compare an RwLock when
substantial independent read work can overlap. Shorten guards when a copied
snapshot preserves the contract. Large immutable tables may favor publication
with safe reclamation; sharding fits independent keys. Record freshness, memory,
writer progress, and reclamation costs before substituting a topology.

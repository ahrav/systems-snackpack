# Runtime-resolved x86-64 host

## Measurement boundary

The Secure Shell (SSH) alias `xxl` resolved during this run to
`dev-dsk-ahrav-2c-32182091.us-west-2.amazon.com`. The accepted campaign ran
from `2026-08-29T17:01:24Z` through `2026-08-29T17:01:28Z`. It used source
commit `97572e93a6ee98e14bece7501068d5cedd962571` and source-archive SHA-256
`546dd1fa3cd205fd19bc937198281e0b7b6ca929a85d657c18f68d8312c4d035`.
The native binary SHA-256 was
`0a53d4e0079aa4fa0acfe2ce9a6730e6a96c80542a4bf303b6d5b75c4820a699`.

The host reported:

- `x86_64`, kernel `6.12.95-124.187.amzn2023.x86_64` with
  `PREEMPT_DYNAMIC`;
- 192 configured and 192 affinity-allowed logical CPUs;
- Intel Xeon Platinum 8488C, two sockets, 48 cores per socket, and two threads
  per core, exposed through a Kernel-based Virtual Machine (KVM) guest;
- holder CPU 0, waiter CPU 1, and control CPU 2 on three distinct physical
  core identifiers; CPU 96 was the recorded SMT sibling of holder CPU 0;
- SMT state `1` and control `on`;
- GNU Compiler Collection (GCC) 11.5.0 and Python 3.9.25;
- build flags `-O2 -g -std=c11 -Wall -Wextra -Werror -pthread`;
- no exposed CPU-frequency policy files; and
- two guest CPU-idle choices for selected CPUs: polling and `haltpoll`, with
  reported exit latencies of 0 and 1 microsecond.

Guest topology and idle interfaces are provider-selected evidence. They do not
prove host-physical placement or hardware residency below the virtual machine.

## Exact-host result

Each label contains 16 fresh processes. A complete four-process block is one
replication, so every interval below uses eight block contrasts.

|---|---:|---:|
| Median holder thread CPU time | 5.008643 ms | 5.009310 ms |
| Median holder wall time | 192.205819 ms | 5.009945 ms |
| Median waiter lock time | 201.246208 ms | 5.016148 ms |
| Median holder involuntary context switches | 1 | 0 |
| Median complete process-attempt wall time | 203.219647 ms | 6.870785 ms |

The holder-wall A/B geometric ratio was `38.855392`, with a two-sided 95%
Student-t interval of `[38.233483, 39.487418]`. The waiter-lock A/B ratio was
`40.144134`, with interval `[39.715955, 40.576930]`.

The complete attempt time includes fresh-process startup, thread creation, the
measured work, and exit. It is retained separately. The primary holder and
waiter intervals start inside the process after thread placement and the start
barrier, so they exclude compilation and process startup. The experiment does
not estimate startup as its own component.

The mechanically identical X/Y A/A holder-wall ratio was `1.000087`, with
interval `[0.997937, 1.002242]`. Its waiter ratio was `1.000100`, with interval
`[0.998055, 1.002149]`. A/A is a path-asymmetry check, not a noise floor.

All 64 rows used distinct process identifiers. Every holder measured from 4.9
through 6.0 milliseconds of thread CPU time. Affinity, start and end CPUs,
scheduling policy, static priority, nice values, source hashes, and binary
hashes passed independent validation. No attempt failed.

## Linked-code observation

The linked x86-64 `burn_thread_cpu` function remains a distinct symbol. Its
inner loop reloads and stores the volatile state, applies `shl`/`xor` and
`shr`/`xor`, multiplies with `imul`, counts 4,096 iterations with `sub`/`jne`,
calls `clock_gettime(CLOCK_THREAD_CPUTIME_ID)`, and loops until the CPU-time
target. `holder_main` calls this symbol while the mutex is held. This
establishes the linked code shape; it does not identify a scheduler decision or
compare instruction costs with Arm.

## Measured and inferred

Measured: thread CPU and wall time, waiter lock time, context-switch counts,
thread placement and scheduler readback, host metadata, exact source and binary
identity, and linked disassembly.

Inferred: the 39-fold wall expansion with nearly unchanged holder CPU time is
consistent with the nice-19 owner being descheduled by the normal-priority hog.
The involuntary context-switch counts support that explanation but do not make
it unique.

A separate read-only probe at `2026-08-29T17:04:05Z` observed
`/sys/kernel/sched_ext/state=disabled` and
`/proc/sys/kernel/sched_schedstats=0`. It was collected after the campaign, so
it is not rewritten as an in-receipt or whole-window observation.

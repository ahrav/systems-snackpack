# Round 1: body visibility

## Decision rule

Classify a missed optimization before changing code:

- legality: would the result remain valid for every permitted execution?
- visibility: are the body, values, aliases, and effects available together?
- binding: may this definition replace the runtime-resolved symbol?
- timing: did the relevant pass run after the facts became available?
- profitability: did the target cost model accept code-size and register costs?

Use optimization remarks and IR to distinguish legality from profitability,
then inspect the final linked call site. Source attributes alone are
insufficient evidence.

## Cost model

Crossing the boundary can save dispatch and expose constant propagation,
hoisting, dead-code elimination, and vectorization. It can also clone code,
increase register pressure and spills, add runtime alias checks, and consume
instruction-cache and link resources.

The focused experiment changes body visibility while holding the scalar
operation fixed. Its opaque/visible timing ratio includes every downstream
consequence, including vectorization and loop shape; it is not a call-latency
measurement.

## Evidence limits

- A vanished call does not, by itself, prove source-level inlining.
- An exported symbol does not prove local callers use it.
- Equal source expressions do not prove equal final machine code.
- Equal machine code does not prove an impenetrable optimizer boundary.
- One host and compiler build do not establish an ISA-wide result.

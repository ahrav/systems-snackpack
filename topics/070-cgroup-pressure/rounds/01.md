# Round 01: budget, timing and pressure

CPU time is a shared budget. With 50 ms quota per 100 ms period, one runnable
worker ideally burns for 50 ms while four burn for 12.5 ms. Both have half a
CPU of long-run allowance. Real slices, arrivals and ancestors alter timing.

CPU quota, weight and eligible CPUs are separate controls. cpu.stat identifies
fair-bandwidth enforcement; PSI measures stalled wall time. Neither a raw
cumulative value nor a reused cgroup path supplies a valid incident delta.

For memory, high triggers reclaim/throttling while max provides hard
containment. Four retained 32 MiB buffers plus 16 MiB shared state need about
144 MiB, versus 48 MiB for one worker. This is a derived application model,
not measured charged memory or a claim that one memory policy wins.

Long-run completion estimates divide CPU work by available service rate.
They are not finite-batch lower bounds: a fresh quota can allow a short batch
to finish before the first interruption. The executable compares both sizes
and both periods to expose this distinction.

Full teaching material is retained outside Git. This crate preserves the
implementation, protocol, compact results and source identities.

## Workload and result

The run used a prewarmed 512 MiB file on memory-backed temporary storage, an
IPv4 loopback TCP socket, and 256 KiB requested chunks. Each of eight paired,
order-balanced blocks contained four fresh processes. There was no retry.

| `splice` / buffered | 8 | 32 | 0.558441 | [0.548789, 0.568263] | 0.107724 s | 0.193719 s |
| buffered label B / buffered label A | 8 | 32 | 1.003497 | [0.995345, 1.011716] | same method | same method |

Median sender CPU time was 0.194296 s for buffered, 0.052837 s for `sendfile`,
and 0.057600 s for `splice`. Receiver CPU time rose from about 0.052 s for the
buffered path to about 0.108 s for both copy-avoiding paths. Those CPU medians
are descriptive process observations, not paired interval estimates.

The observed pipe capacity was 65,536 bytes. For 512 MiB, `splice` made 8,192
file-to-pipe and 8,192 pipe-to-socket calls. Buffered made 2,048 `pread` and
2,048 `send` calls; `sendfile` made 2,048 calls. Exact-byte correctness passed
for 16,777,219 bytes through every method.

The `MSG_ZEROCOPY` control verified 524,288 received bytes and completion
ranges `[0,0]` and `[1,7]`. Both notifications had zero error and reported the
documented copied fallback on loopback. The control reported no timing.

Linked disassembly contained external calls to `pread`, `send`, `sendfile`,
and two `splice` sites. This is generated-code evidence about the executable,
not proof of the executed branch or the cause of an elapsed difference.

## Boundary

`transfer_sec` includes buffered allocation/free and `splice` pipe
create/close, but excludes socket and file setup. The asymmetry prevents a
copy-only causal interpretation. The result excludes storage misses, a NIC,
DMA, a remote receiver, TLS, congestion, concurrency, and tail latency. It
describes this host and run only, not Arm processors generally.

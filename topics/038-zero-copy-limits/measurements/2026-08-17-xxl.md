## Boundary

`transfer_sec` starts after input-file open and sender socket connect. It
includes buffer allocation and release for buffered I/O and pipe creation and
close for `splice`. There is no receiver-ready barrier, so receiver `accept`
and buffer allocation can overlap the beginning. It ends after sender shutdown,
receiver report collection, and child exit. Sender CPU covers this interval;
receiver CPU covers the child's whole lifetime. This timer asymmetry is part of
the declared treatment, so the elapsed ratios cannot isolate byte-copy cost.

Measured evidence consists of process times and CPU intervals, exact byte
counts and completed non-`EINTR` operation counts, pipe and socket sizes,
completion records, host and toolchain
metadata, hashes, and linked call sites. Ratios, medians, dispersion, and CIs
are derived summaries. Copy removal, cache, page-reference, protocol, and
scheduler explanations remain inferred because this run did not isolate them.

The result excludes storage misses, a network interface card (NIC), direct
memory access (DMA), a remote receiver, Transport Layer Security (TLS),
congestion, concurrency, and tail latency. It describes this resolved host and
one sequential run only; it does not establish a property of x86-64 processors.

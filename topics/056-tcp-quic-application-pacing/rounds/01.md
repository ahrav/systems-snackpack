# Round 01: pause credit and admission ownership

The running example uses chunk size S=1,200 bytes, admission rate r=12,000,000
bytes/s, and bucket capacity B=2,400 bytes. The nominal interval is
S/r=0.0001 s=100 microseconds. Wakeups from 2,000 through 6,900 microseconds are
omitted; processing resumes at 7,000 microseconds.

The overdue loop includes the current deadline. Its five-millisecond lateness
therefore yields floor(5,000/100)+1=51 chunks, or 61,200 bytes, in one wakeup.
At a hypothetical constant downstream rate C=12,000,000 bytes/s, this burst
needs Q/C=61,200/12,000,000=5.1 ms to drain. That is a queue-model calculation,
not an observed transport delay.

The bucket refills as min(B, credit+r*elapsed) and charges actual accepted bytes.
After the last pre-pause wakeup at 1,900 microseconds, 5.1 ms of elapsed time
produces min(2,400, 12,000,000*0.0051)=2,400 bytes of usable credit.
The cap discards excess permission. It bounds every interval by B+r*elapsed,
which is 2,400 bytes at zero duration and 14,400 bytes over one millisecond.

A target r=12 MB/s over round-trip time R=20 ms needs roughly rR=240,000 bytes
of usable window. A 120,000-byte effective window gives the simplified ceiling
W/R=120,000/0.02=6 MB/s. These models exclude headers, losses, competing traffic,
and changing credit. An application pacing rule cannot manufacture transport
window credit.

## Evidence progression

The initial standalone example ran before repository mutation on both required
Linux hosts. Source SHA-256 was
`5cfda5a8e756ec54eb98eadba08308be6e7fd1278f7fd4e9a728c5b67a6dc772`.
Both returned:

```text
pause=false overdue_burst=1 capped_burst=2 overdue_finish_us=9900 capped_finish_us=9800
pause=true overdue_burst=51 capped_burst=2 overdue_finish_us=9900 capped_finish_us=14700
```

Each treatment admits 100 chunks. The no-pause control, full initial bucket,
wakeup grid, and equal total work are explicit. Every contiguous interval in
the capped trace is checked. The library adds partial/blocked write accounting,
fractional refill, overflow-range and clock-regression tests.

The initial Arm host had 64 online CPUs, Linux 6.12.100-125.179.amzn2023.aarch64,
and rustc 1.95.0. Runtime-resolved xxl was
dev-dsk-ahrav-2c-32182091.us-west-2.amazon.com, x86-64, with 192 online CPUs,
Intel Xeon Platinum 8488C, Linux 6.12.95-124.187.amzn2023.x86_64, and rustc 1.98.0.
Both builds used edition 2024, warnings denied, opt-level=2, and the compiler's
default target CPU/features. The final committed-source campaign is a separate
required gate, recorded under measurements when complete.

No timing comparison is useful for this correctness experiment: elapsed CPU
time would measure the model and its exhaustive assertions, not transport
performance. The pause is injected in a logical clock. Results establish only
the tested admission transitions, not kernel timer behavior or network delivery.
The interval oracle uses the timestamp supplied to each admission attempt.
Preemption inside an attempt, between the clock check and actual acceptance,
is outside that oracle. The implementation does not guarantee a strict
wall-clock acceptance envelope when those operations are separated by delays.

## Live follow-on boundary

A later network experiment must record application acceptance, transport
queueing, and useful peer delivery separately. Use paired order-balanced process
runs with a fixed route, payload, controller, receiver, and offered load. Record
run count and dispersion, and separate startup from steady state. Wire pacing
needs departure evidence beyond segmentation and buffering boundaries.

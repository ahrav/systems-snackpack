## Correctness observations

Each of four fresh processes mapped 512 MiB as 131,072 base pages. The process
first wrote one next-page index per page on CPU 0, then completed four full
single-cycle pointer-chase passes, or 524,288 dependent loads.

- Every page was observed on node 0 before and after every chase.
- Every measured chase had zero minor and major faults.
- `MADV_NOHUGEPAGE` succeeded; `/proc/self/smaps` reported the exact VMA with
  `AnonHugePages: 0`, `THPeligible: 0`, and the no-huge-page flag.
- Every checksum matched the independent expected-chain calculation.
- Diagnostic read times were 75.764, 74.602, 75.404, and 74.807 ms.
- The wrapper, all six Cargo gates, native build, receipt validator, final
  source-manifest comparison, and evidence hash manifest passed.

Linked-image inspection showed one address-dependent scalar `ldr` in the inner
loop. The loaded page index feeds the address multiply for the next iteration.
That proves the intended dependency chain in this binary. It does not prove
memory-controller traffic; page placement comes from `move_pages(2)` queries.

## Claim boundary

This is measured correctness and observed code generation on one exact Arm
host. It says nothing about remote-memory cost, migration break-even, other Arm

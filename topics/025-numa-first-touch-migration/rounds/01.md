# Round 1: First-touch ownership and worker migration

Date: 2026-08-04

## Question

When anonymous pages are first written on one NUMA node, how much does a fixed
dependent-read workload change when its worker stays on that node versus moves
to the other node, and how many future remote accesses would repay migration or
replication?

## Decision

Use a controlled first-touch experiment plus a separate pure cost model.
Timing alone cannot establish locality, and a placement experiment cannot
price long-lived migration without a declared workload horizon.

The checked-in candidate must:

- allocate anonymous memory in a fresh process and request base-page behavior;
- pin the initializer, write one next-page index per page, then query every page;
- pin the worker independently and perform the fixed dependent access pattern;
- query every page again outside the timer;
- record CPU, node, fault counts, page statuses, checksum, and final code shape;
- exercise both data-node directions on a two-node host and degrade to a
  correctness-only control on a one-node host.

## Experimental units and schedule

One fresh process is one treatment application. One complete four-process
`ABBA` or `BAAB` block is one analysis unit; the inner dependent loads are
subsamples. Direction is a separate estimand because node 0 to node 1 need not
equal node 1 to node 0.

For each two-node direction:

- `A`: first-touch node and worker node are equal;
- `B`: pages remain on the declared data node while the worker runs on the
  other node;
- stopping rule: eight complete A/B blocks;
- negative control: four complete A/A blocks through the same schedule paths;
- estimator: geometric remote/local elapsed ratio from block log contrasts;
- interval: two-sided 95% Student-t interval over complete block log contrasts.

Every attempted process remains in the ledger. A process with a source,
affinity, placement, fault, or checksum failure is excluded by the declared
gate and is not replaced after its outcome is observed. The run is incomplete
if the fixed number of valid blocks was not scheduled as declared.

## Model boundary

The crate compares these totals over one horizon:

```text
keep remote:  A * Lr
migrate:      Cm + A * Ll
replicate:    Cr + W * Cs + A * Ll
```

It assumes the action turns all modeled remote accesses into local accesses.
It does not model partial hot-page migration, concurrent ownership, cache
coherence, queuing, saturation, or Linux's balancing feedback loop. Measure
those mechanisms before adding them to a claim.

## Pre-artifact observation

A 2026-08-04 two-node x86 scratch probe produced remote/local ratios above 1.5
in both directions with A/A intervals spanning 1.0, while a one-node Arm host
could provide only placement and correctness control. These values motivated
the design but came from scratch source `c4a2c445...`, not this directory. The
full provisional values are recorded in the [topic README](../README.md).

## Promotion gates

The checked-in result supersedes the scratch observation only after:

1. exact source and final binaries are hashed on both hosts;
2. topology, policy, affinity, huge-page state, and automatic balancing are
   recorded;
3. every page is on the intended node before and after each valid process;
4. all fixed A/B and A/A blocks complete with zero measured-phase faults and
   matching checksums;
5. linked-image inspection confirms the intended dependent access chain;
6. raw evidence, summaries, status, and their SHA-256 manifest are retained.

Even after those gates, the claim remains scoped to the measured hosts,
direction, mapping, access pattern, build, policy state, and run window.

# Round 1: fixed useful work across vector widths

Date: 2026-08-24

## Question

For one fixed compute-bound recurrence, how do scalar, 128-bit, 256-bit, and
512-bit paths change elapsed time and generated code on the two required Linux
hosts? On x86-64, does the grouped cycle-to-reference-cycle ratio move with the
512-bit path?

## Fixed comparison

Every mode performs the same recurrence step count over 96 logical
double-precision chains. Twelve independent accumulators expose parallel work.
The benchmark compiles with `-fno-tree-vectorize`, so the scalar oracle remains
scalar and each intrinsic path fixes its width. A same-mode warmup precedes the
main interval measured by Linux `CLOCK_MONOTONIC_RAW`, a monotonic clock not
adjusted by wall-clock corrections.

The baseline mode is A and the candidate mode is B. Each comparison uses eight
seed-shuffled ABBA or BAAB blocks, which place both modes in early and late
positions. Every letter is a fresh process pinned to one logical central
processing unit (CPU). A block log contrast is the average logarithm of the two
candidate times minus the average logarithm of the two baseline times. One
complete four-process block is one replication. Eight A/A blocks assign both
labels to the same mode and screen order and label imbalance. The experiment
fixes the schedule before observing results and never replaces a failed process.

## Acceptance contract

Each required Linux host must:

1. execute source extracted from one Secure Hash Algorithm 256-bit (SHA-256)
   digest-checked Git archive with its full commit identity;
2. record the Secure Shell (SSH) target label, resolved and runtime hostnames,
   architecture, kernel, central processing unit (CPU) model, available CPU
   count, selected CPU, sibling topology, toolchains, build flags, and features;
3. require `xxl` to resolve to `x86_64`, and require
   `dev-dsk-ahrav-2b-7dc7bd93.us-west-2.amazon.com` to report `aarch64` or
   `arm64`;
4. pass the crate tests and the C benchmark correctness oracle;
5. retain the executable digest and disassembly for every supported kernel;
6. show scalar fused multiply-add instructions and the intended packed width in
   each vector kernel;
7. complete eight blocks for every supported comparison and eight A/A blocks,
   with zero failed processes and zero CPU-placement mismatches;
8. retain raw process rows, block contrasts, summaries, counter running time,
   startup and warmup boundaries, and per-CPU steal-tick deltas, which count
   scheduler-accounting intervals when a virtual CPU wanted to run but the
   hypervisor did not schedule it;
9. independently recompute each point estimate and 95% interval from raw rows;
10. prove the extracted source stayed unchanged and pass receipt validation.

The A/A geometric mean must remain in `[0.90, 1.10]`. On x86-64, grouped
user-mode core cycles and reference cycles must each run at least 99% of the
enabled time. Arm must record user-mode core cycles at the same threshold; its
host need not expose reference cycles.

## Expected observations

All modes must pass the scalar checksum tolerance. x86-64 code generation must
contain scalar, XMM 128-bit, YMM 256-bit, and ZMM 512-bit fused multiply-add
loops when the host exposes the required features. XMM, YMM, and ZMM are the
x86 architectural names for 128-bit, 256-bit, and 512-bit vector registers.
AArch64 code generation must contain scalar `fmadd` and 128-bit Advanced Single
Instruction, Multiple Data (Advanced SIMD) `fmla` loops.

A wider path can take less time without reaching its ideal lane-count speedup.
On x86-64, a lower cycles-to-reference-cycles ratio during the 512-bit process
would be consistent with a lower effective clock. A frequency license is an
internal processor classification used to select an allowed power and clock
range. This result would not prove a license transition because the counter
boundary also includes startup and warmup, and the protocol does not retain a
direct license-state observation.

## Controls and evidence boundary

- **Positive oracle:** Every supported vector mode must match the scalar
  recurrence within the stated floating-point tolerance.
- **Negative implementation check:** An Arm intrinsic operand-order mistake can
  preserve the mathematical recurrence while copying a constant into a
  temporary destination on every update. The generated-code gate requires 12
  independent `fmla` destinations and rejects vector-register copy instructions
  inside the detected hot loop.
- **A/A control:** Identical code receives both labels under the same block
  schedule.
- **Order control:** Equal-count ABBA and BAAB templates cancel linear drift
  inside each complete block.
- **Placement control:** `taskset` pins each process; the binary reports its
  observed CPU.
- **Counter control:** The minimal x86 group measures user-mode core and
  reference cycles simultaneously. Counter multiplexing means time-sharing
  limited hardware counters; the validator rejects a record when either event
  ran for less than 99% of its enabled time.
- **Measured:** fixed-work elapsed time, process-level variation, selected
  user-mode hardware counters, code generation, host identity, toolchain, and
  flags.
- **Inferred:** a width or effective-clock mechanism consistent with a ratio.
- **Not tested:** memory-bound work, short-request crossover, Scalable Vector
  Extension (SVE) execution, multi-core frequency domains, simultaneous
  multithreading interference, thermal causality, every compiler, or another
  processor model.

The recorded steal-tick delta comes from Linux's per-CPU accounting of time a
virtual processor wanted to run but the hypervisor did not schedule it. A zero
delta does not rule out every form of virtual-machine interference.

The paired 95% Student-t interval describes uncertainty across the eight
fresh-process block contrasts during one run window. Exponentiating the
log-contrast standard deviation gives the multiplicative standard-deviation
factor. Neither measure covers host selection, compiler selection, workload
selection, or future system state.

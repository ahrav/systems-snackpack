# `xxl` checked-source observations

Date: 2026-08-24

## What this run tested

This run compared fixed useful work in scalar, 128-bit, 256-bit, and 512-bit
fused multiply-add loops on one pinned logical central processing unit (CPU).
It tested correctness, generated code, steady-state kernel time, and grouped
user-mode core-cycle and reference-cycle counters. A reference cycle advances
independently of frequency scaling when the host exposes that event. The run did
not test memory-bound work, short requests, multiple active cores, a complete
service, or another processor model.

The Secure Shell (SSH) alias `xxl` resolved at run time to
`dev-dsk-ahrav-2c-32182091.us-west-2.amazon.com`. That host reported `x86_64`.
The executed source was commit
`edc75b260d1909bb9c4d043cbfadba5e98e38944` in a scoped Git archive with
Secure Hash Algorithm 256-bit (SHA-256) digest
`1c1f7c89a513ec6409367b3b5605def6748ba95d2a9f1a55fcfe67c111031852`.

## Timing observations

The baseline mode is A and the candidate mode is B. Every comparison used eight
ABBA or BAAB order-balanced blocks, placing both modes in early and late
positions. Each block contained four fresh processes. Its log contrast is the
average logarithm of the two candidate times minus the average logarithm of the
two baseline times, and one block is one replication. The paired Student-t
interval describes uncertainty across eight block contrasts. The
multiplicative standard deviation is the factor obtained by exponentiating the
log-contrast standard deviation. These statistics cover between-block variation
in this run window, not host or workload selection. An A/A control assigns both
labels to the same mode.

| Comparison | Candidate/baseline time | 95% interval | Multiplicative standard deviation |
| --- | ---: | ---: | ---: |
| Scalar to 128 bit | 0.499846 | [0.499454, 0.500239] | 1.000940 |
| Scalar to 256 bit | 0.250132 | [0.250071, 0.250193] | 1.000291 |
| Scalar to 512 bit | 0.148387 | [0.148336, 0.148437] | 1.000407 |
| 128 bit to 256 bit | 0.500364 | [0.500238, 0.500489] | 1.000301 |
| 256 bit to 512 bit | 0.593238 | [0.592954, 0.593522] | 1.000573 |
| 256-bit A/A control | 1.000088 | [0.999802, 1.000374] | 1.000342 |

For the direct 256-bit to 512-bit comparison, median main-kernel time was
75.201 ms for 256 bit and 44.611 ms for 512 bit. The paired point estimate is a
1.686-fold speedup, less than the ideal twofold lane-count speedup.

The median user-mode core-cycles-to-reference-cycles witness was 1.333555 for the
256-bit processes and 1.126067 for the 512-bit processes, a ratio of 0.844410.
Median user-mode core cycles had a candidate-to-baseline ratio of 0.501404.
Dividing that process-scope counter ratio by the witness ratio gives a
diagnostic estimate of 0.593792. It differs from the main-kernel time ratio of
0.593238 by 0.000554, or 0.093%. This is a consistency check, not an independent
prediction, because both counter ratios come from the same runs and cover a
different scope from the main timer.

Those user-mode counters ran simultaneously at 100% of enabled time, but Linux
`perf stat` covered process startup, warmup, and the main kernel. The Linux
`cpufreq` frequency interface was absent, and the `turbostat` frequency tool was
unavailable. A frequency license is an internal processor power-and-clock
classification. No direct Advanced Vector Extensions 512 (AVX-512) license or
frequency observation was retained. The ratio is consistent with a lower
effective clock during the 512-bit process; it does not establish the causal
mechanism or a processor-wide frequency rule.

## Correctness and generated code

Every supported mode matched the scalar oracle within its floating-point
tolerance. Zero of 192 fresh-process attempts failed, moved off CPU 24, or
observed steal-tick growth, meaning Linux recorded no time in which the virtual
CPU waited for the hypervisor to schedule it at the counter's accounting
resolution. The retained executable SHA-256 digest is
`ea9098ad2a85a4bcf827190e623148e9a36386f04db74609355403b6d749cb5b`.

Machine inspection found 12 independent fused multiply-add destinations in
each measured hot loop. XMM, YMM, and ZMM are the x86 architectural names for
128-bit, 256-bit, and 512-bit vector registers. The scalar and 128-bit paths
used XMM registers, the 256-bit path used YMM registers, and the 512-bit path
used ZMM registers. The checker found no memory operand and no `mov` or `vmov`
mnemonic inside those compute loops. This proves the recorded binary's width
shape, not that another compiler or processor would choose or execute the same
shape.

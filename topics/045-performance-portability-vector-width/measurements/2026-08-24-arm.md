# Arm checked-source observations

Date: 2026-08-24

## What this run tested

This run compared fixed useful work in scalar and 128-bit Advanced Single
Instruction, Multiple Data (Advanced SIMD, also called NEON) fused multiply-add
loops on one pinned logical central processing unit (CPU). It tested
correctness, generated code, steady-state kernel time, and user-mode core
cycles. It did not execute a Scalable Vector Extension (SVE) path or test
memory-bound work, short requests, multiple active cores, or another processor
model.

The fixed target `dev-dsk-ahrav-2b-7dc7bd93.us-west-2.amazon.com` reported
`aarch64`. The executed source was commit
`edc75b260d1909bb9c4d043cbfadba5e98e38944` in a scoped Git archive with
Secure Hash Algorithm 256-bit (SHA-256) digest
`1c1f7c89a513ec6409367b3b5605def6748ba95d2a9f1a55fcfe67c111031852`.

## Timing observations

The baseline mode is A and the candidate mode is B. Each comparison used eight
ABBA or BAAB order-balanced blocks, placing both modes in early and late
positions. Each block contained four fresh processes. Its log contrast is the
average logarithm of the two candidate times minus the average logarithm of the
two baseline times, and one block is one replication. The paired Student-t
interval describes uncertainty across the eight block contrasts. The
multiplicative standard deviation is the factor obtained by exponentiating the
log-contrast standard deviation. These statistics cover between-block variation
in this run window, not host or workload selection. An A/A control assigns both
labels to the same mode.

| Comparison | Candidate/baseline time | 95% interval | Multiplicative standard deviation |
| --- | ---: | ---: | ---: |
| Scalar to 128 bit | 0.494984 | [0.486690, 0.503419] | 1.020414 |
| 128-bit A/A control | 1.005739 | [0.983666, 1.028308] | 1.026896 |

Median main-kernel time was 369.869 ms for scalar and 184.897 ms for 128 bit.
The paired point estimate is a 2.020-fold speedup for this recurrence. The wider
A/A interval shows that this host's process-level timing varied more than the
x86 run; inner-loop steps are not independent samples and were not counted as
such.

The host exposed user-mode core cycles but not reference cycles, which advance
independently of frequency scaling, so this run cannot make a clock-ratio
observation. The main timer excluded startup and same-mode warmup; the user-mode
core-cycle counter surrounded the child process and included both. It ran for
100% of enabled time. Zero of 64 fresh-process attempts failed, moved off CPU
16, or observed steal-tick growth, meaning Linux recorded no time in which the
virtual CPU waited for the hypervisor to schedule it at the counter's accounting
resolution. These results do not predict an SVE width or an Arm-family speedup.

## Correctness and generated code

Both modes matched the scalar oracle within its floating-point tolerance. The
retained executable SHA-256 digest is
`ae4ca16e399cc45bee0d950c771559cd504ac8a240f02f38d22880e14565c4a8`.

Machine inspection found 12 independent scalar `fmadd` destinations and 12
independent 128-bit `fmla` destinations. These are the AArch64 assembly
mnemonics for scalar and vector fused multiply-add. No register-copy or memory
instruction appeared in either detected compute loop. The retained result
proves the recorded source and code shape only.

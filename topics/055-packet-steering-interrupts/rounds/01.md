# Round 01: packet steering and interrupt placement

This visit separates five decisions in the Linux network path: RSS queue
selection, IRQ affinity, NAPI polling, optional RPS or RFS receive placement,
and XPS transmit-queue placement. It models receive-queue utilization,
interrupt batching cost, RPS remote-placement cost, RFS locality and migration
cost, flow-table aliases, and XPS locality savings.

The focused UDP experiment compares one flow with 128 flows while holding the
total number of byte-validated request and echo pairs constant. It keeps every
client socket alive, records distinct source endpoints, and checks peer, NAPI,
and CPU stability separately on the required Arm and x86-64 Linux hosts.

The visit does not claim that a NAPI identifier names an RSS table entry, that
an interrupt equals one packet, that a shared server socket proves RFS
placement, or that a cross-host difference comes from the instruction set. It
also does not treat scratch-source runs, loopback traffic, or configuration
files without execution evidence as publication results.

The final exact-source campaign passed 24 fresh bidirectional periods and two
independent sealed-receipt validations. Each 128-flow run observed eight
stable positive NAPI identifiers on the eight-queue Arm host and 16 on the
16-queue `xxl` host while every observed software-steering map remained zero.
This is a topology observation, not a performance or RSS-table measurement.

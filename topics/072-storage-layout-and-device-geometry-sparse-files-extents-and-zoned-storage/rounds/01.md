# Round 1: bytes, reservations, and placement

Date: 2026-10-09. Topic 072.

A 16 MiB logical file receives 64 writes of 4 KiB, one every 256 KiB.
The populated fraction is 1/64, or 1.5625%. All three initializers must
produce identical bytes, then pass an independent full-byte oracle after
both the initial patch and one overwrite pass.

Sparse length extension leaves logical zero ranges without reserving their
future storage. Mode-0 fallocate reserves space and may leave unwritten
extents. Explicit zero fill writes the whole logical length. A byte read
alone cannot distinguish those allocation states.

The timing boundary is file open/create + initialization + patch + sync,
then overwrite + sync. Verification between phases is excluded and warms
the overwrite cache. Offset-list and buffer preparation, startup, reporting,
and close/unlink are excluded; close/unlink duration is recorded separately.
This is a finite fresh-file workload, not steady-state throughput or a
crash-recovery experiment. Directory durability is not implemented.

Linux st_blocks uses 512-byte units. Record whether the file is still open.
XFS speculative allocation can make inode accounting exceed logical size;
a post-close sample may differ. FIEMAP is a filesystem mapping snapshot,
not physical flash geometry. Extent row count alone does not predict latency.

This discussion and the cursor model cover sequential-write-required zones.
For such a zone, usable capacity can be less than its address-space
size. With size 256 MiB, capacity 240 MiB and used 236 MiB, an 8 MiB append
must fail even though it ends before the next zone. The next zone starts
at 256 MiB. The cursor checks alignment and overflow and does not advance
on rejection. Real devices also need ownership, issue ordering, open/active
admission, returned append-address handling, and failure reconciliation.
The two measured hosts have non-zoned devices; those mechanisms are unmeasured.

Choose sparse for low occupancy when future allocation is acceptable.
Choose preallocation for reservation. Choose explicit zero fill only when
materialization is required or the complete measured workload benefits.
Use the committed-source result table for host/workload timing selection.

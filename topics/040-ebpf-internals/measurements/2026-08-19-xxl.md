## Question and boundary

This run asks whether one exact committed probe reaches the expected Linux
permission, verifier, translation, socket-attachment, and packet-action
boundaries on the runtime-resolved `xxl` host. It does not measure elapsed time.
The 250-millisecond drop timeout is a correctness threshold.

## Observations

- The ordinary process exited 77. Both load attempts returned `EPERM`, and the
  verifier logs were empty. This is the observed host policy ordering.
- All eight independently launched privileged processes passed without retry.
- Every process rejected the invalid program with `EINVAL` and
  `jump out of range from insn 0 to 101`.
- Every process loaded both valid programs, received the exact 14-byte accept
  payload, and observed a successful send followed by a receive timeout for
  drop.
- Both translated programs were 16 bytes and matched the submitted encodings.
- All eight accept JIT blobs were the same 21 bytes. All eight drop JIT blobs
  were the same 16 bytes. Each of the 16 disassemblies contained native code
  ending in `ret`.
- The Rust library/example tests and deterministic example passed from the same
  Git archive.

The visible accept body used `mov $-1, %rax`; the shorter drop body used
`xor %eax, %eax`. Both included no-operation prefixes, a frame prologue,
`leave`, and `ret`. The receipt establishes those bytes; it does not establish
the purpose of the no-operation prefix without exact kernel-source correlation.

`bpf_prog_info` reported zero runtime counters while socket behavior proved
execution. Runtime statistics were disabled.

## Evidence boundary

The process success rate, bytes, disassembly, host identity, and configuration
are measured. The verifier, JIT, and socket contracts are source-backed. Any
claim about other x86-64 systems or relative performance would be an
unsupported inference.

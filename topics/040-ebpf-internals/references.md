# Primary sources and Linux 6.12 boundary

The retained targets run Amazon Linux kernels derived from Linux 6.12. The
documentation links below select the Linux 6.12 documentation where that site
publishes a versioned page. Mainline documentation can describe later behavior
and is not evidence about the measured hosts. Recheck the exact deployed
kernel configuration, permission policy, program type, attach target, and
driver before applying a mechanism operationally.

## Instruction and verifier contracts

- [RFC 9669: BPF Instruction Set Architecture (ISA), version 1.0](https://www.rfc-editor.org/rfc/rfc9669.html)
  defines the BPF instruction encoding, registers, memory operations, jumps,
  and calling convention. It does not define Linux program types or the Linux
  helper catalog and contracts.
- [Linux 6.12 eBPF verifier documentation](https://docs.kernel.org/6.12/bpf/verifier.html)
  describes register and stack state, pointer types, value ranges, branch
  refinement, and state pruning. Its broad statement that loops are not allowed
  is stale for this release: bounded-loop support entered Linux in 5.3.
- [Linux 6.12 eBPF design questions and answers](https://docs.kernel.org/6.12/bpf/bpf_design_QA.html)
  states stability boundaries and explains verifier and instruction-limit
  expectations. Its loop discussion also preserves older wording; use the
  [Linux 5.3 bounded-loop implementation commit](https://github.com/torvalds/linux/commit/2589726d12a1b12eaaa93c7f1ea64287e383c7a5)
  and the exact deployed verifier as the implementation boundary.
- [Linux 6.12 verifier implementation](https://github.com/torvalds/linux/blob/v6.12/kernel/bpf/verifier.c)
  is the source-level boundary for claims that the shorter design document does
  not specify. Distribution kernels can carry backports or changes.

## Loading, types, and lifetime

- [Linux `bpf()` system call manual](https://man7.org/linux/man-pages/man2/bpf.2.html)
  defines program and map creation through file descriptors and describes
  verifier logging. The manual tracks the Linux user API rather than one
  distribution kernel build.
- [Linux 6.12 `bpf()` implementation](https://github.com/torvalds/linux/blob/v6.12/kernel/bpf/syscall.c)
  shows object creation and file-descriptor ownership in that kernel release.
- [Linux 6.12 BPF Type Format documentation](https://docs.kernel.org/6.12/bpf/btf.html)
  defines BTF type and relocation records used by loaders and introspection.
- [libbpf overview](https://docs.kernel.org/bpf/libbpf/libbpf_overview.html)
  describes object open, load, attach, and teardown stages. This page tracks
  current mainline and is not a Linux 6.12 snapshot.
- [Linux 6.12 BPF filesystem implementation](https://github.com/torvalds/linux/blob/v6.12/kernel/bpf/inode.c)
  implements pin and lookup operations for supported kernel BPF objects.

## Hooks, helpers, maps, and output

- [Linux 6.12 program types and expected attach types](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/bpf.h)
  provide the UAPI enumeration and command structures used by the experiment.
- [Linux helper manual](https://man7.org/linux/man-pages/man7/bpf-helpers.7.html)
  catalogs helper contracts generated from kernel definitions. Check the
  deployed program type and kernel before using a helper. This unversioned
  manual is not a Linux 6.12 snapshot.
- [Linux 6.12 hash map documentation](https://docs.kernel.org/6.12/bpf/map_hash.html)
  describes updates, concurrency, per-CPU variants, and map-value spin locks.
- [Linux 6.12 ring-buffer documentation](https://docs.kernel.org/6.12/bpf/ringbuf.html)
  defines the shared multi-producer, single-consumer design, record headers,
  reservation failure, ordering, notification, and stalled-reservation catch.
- [Linux 6.12 socket-filter integration](https://github.com/torvalds/linux/blob/v6.12/net/core/filter.c)
  is the kernel-source boundary for the experiment's program type. It is not an
  XDP or traffic-control measurement.

## JIT compilation, policy, and generated code

- [Linux 6.12 network sysctls](https://docs.kernel.org/6.12/admin-guide/sysctl/net.html)
  define `bpf_jit_enable`, `bpf_jit_harden`, and related observability controls.
- [Linux 6.12 kernel sysctls](https://docs.kernel.org/6.12/admin-guide/sysctl/kernel.html)
  define `unprivileged_bpf_disabled`.
- [Linux 6.12 64-bit Arm JIT source](https://github.com/torvalds/linux/blob/v6.12/arch/arm64/net/bpf_jit_comp.c)
  and [64-bit x86 JIT source](https://github.com/torvalds/linux/blob/v6.12/arch/x86/net/bpf_jit_comp.c)
  show architecture-specific translation in that release. Generated bytes in
  this topic are observations of two named hosts, not instruction-set-family
  performance claims.

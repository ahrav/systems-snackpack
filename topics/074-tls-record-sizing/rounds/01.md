# Round 01: authentication boundaries and write granularity

Date: 2026-10-11. Complete lesson delivered in chat before repository mutation.
The baseline uses the default 16384-byte cap; alternatives use 4096 and 1024.
The Rust budget and real OpenSSL TLS fixture distinguish peer receive limits,
local send caps, flushed writes, TLS records, and TCP segments.

The initial local campaign passed 108 process oracles. The 16384 cap won the
single-write 16384 and 1048576-byte cells; four cells remained unresolved.
The exact committed-source campaign also passed 108 processes and selected the
16384 cap in the same two cells, with four unresolved. Results and compact
identities are in results.md and EVIDENCE_RECEIPT.json. Linux replay is
pending authentication. Raw runs remain outside Git.

Review hardening after the campaign: `check.py`, `run.py`, and `analyze.py` use
explicit failures instead of `assert`, so `python -O` keeps every gate active.
`analyze.py` requires all three caps and six blocks per workload and the full
108-row campaign before selecting a winner. `probe.c` reports the loaded
library's version, build date, platform, directories, compiler flags, and CPU
capability string. `run.py` rejects crypto overrides before creating output,
hashes sources before compiling, requires each row to echo its invocation
arguments and the same library identity, records that identity in
`metadata.json` as `library` (the `openssl` CLI banner stays separate as
`openssl_cli`), rechecks source and binary hashes after the campaign, and
publishes `runs.jsonl` only after every gate passes. `test_gates.py` covers
these gates with and without optimization. The receipt's `inputs` hashes
describe `bd99e4bdb3dce73eaa5f33973ec93acd6e0f3c97`, the measured source; a
Linux arm64 replay with the hardened scripts (OpenSSL 3.5.8) selected the same
two 16384 winners and left the same four cells unresolved. It is a smoke
check, not a required Linux result.

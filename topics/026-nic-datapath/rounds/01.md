# Round 1: UDP submission boundaries and receive aggregation

Date: 2026-08-05

User Datagram Protocol (UDP) preserves message boundaries. A network interface
controller (NIC) is the physical device that moves packets, while direct
memory access (DMA) lets that device access mapped memory without a CPU copying
each byte. A central processing unit (CPU) executes the Linux and application
work measured here.

## Question

How do one-datagram sends, `sendmmsg`, and `UDP_SEGMENT` change loopback work
for 32 equal UDP datagrams, and does `UDP_GRO` preserve all message bytes while
delivering one aggregate?

## Decision

Use loopback to test Linux socket semantics and submission cost without
claiming a physical-NIC result. Keep the pure cost model separate. A later
physical-network experiment would need NIC, queue, interrupt, DMA, offload, and
peer evidence that loopback cannot provide.

The checked-in experiment must:

- send 32 datagrams of 1,200 bytes per round with deterministic headers and
  payloads;
- compare scalar `send`, one `sendmmsg` batch, and one `sendmsg` carrying a
  `UDP_SEGMENT` control message;
- retry interrupted calls and handle partial `sendmmsg` completion;
- pin sender and receiver to two allowed, distinct physical cores;
- use acknowledgements to prevent rounds from running ahead of verification;
- prebuild payloads during setup and keep setup, payload construction, and
  warmup outside one contiguous measured send/receive/ack interval;
- record send and receive call counts, CPU time, socket buffers, logical
  datagrams, observed CPUs, and full payload verification;
- run `UDP_GRO` as a separate semantic control, not as a timed treatment.

## Experimental units and schedule

One fresh process is one treatment application. One complete four-process
`ABBA` or `BAAB` block is one analysis unit. Datagrams and rounds inside a
process are subsamples.

For the exact-source candidate:

- `A` is scalar send; `B` is `sendmmsg` for the first comparison;
- `A` is scalar send; `B` is `UDP_SEGMENT` for the second comparison;
- stopping rule: eight complete blocks for each treatment comparison;
- assignment: seed-shuffled, equal-count `ABBA` and `BAAB` templates with seed
  `2620260805`;
- negative diagnostic: four complete A/A blocks through the same schedule,
  with both labels mapped to the same `sendmmsg` binary path;
- per process: 100 warmup rounds and 1,000 measured rounds;
- estimator: geometric candidate/scalar elapsed ratio from complete-block log
  contrasts;
- interval: two-sided 95% Student-t interval over block log contrasts.

The interval summarizes dispersion among blocks in this run window. It treats
block contrasts as independent and normally distributed, but fresh processes
do not establish those assumptions because kernel state, caches, host load, and
thermal state can persist. Read it as a descriptive run-window interval, not a
fleet or repeated-deployment confidence guarantee.

The two primary comparisons consume 64 processes. The A/A diagnostic consumes
16. Two additional fresh processes run the no-GRO and UDP GRO semantic
controls, for 82 attempted processes in the fixed schedule.

The interval covers process variation within one run window. It does not cover
other hosts, kernels, binaries, routes, datagram sizes, batch sizes, traffic,
or physical devices. Every attempted process remains in the ledger. A failed
process does not become a valid sample because a replacement later passes.

## Correctness boundary

Each datagram carries a round, slot, encoded length, and deterministic payload.
The receiver rejects stale rounds, invalid lengths, duplicate slots, and any
payload mismatch. A valid process reports the expected logical-datagram count,
full payload verification, expected checksum, sender and receiver CPUs, and
passing socket-call outcomes.

The `UDP_GRO` control enables GRO on the receive socket. One `recvmsg` can then
return several datagrams in one buffer. The control message supplies segment
size; the receiver splits the aggregate and verifies every original datagram.
Without that control message, a large buffer alone does not prove UDP GRO.

## Pre-artifact observation

Scratch source `99760da7...` and driver `e2f81092...` ran six four-process
blocks per comparison and four A/A blocks on each required host. Both hosts
showed candidate/scalar ratios below one, and both A/A intervals included one.
The separate UDP GRO controls returned all 32 segments with one control
message. The full provisional values and host metadata are in the
[topic README](../README.md).

These observations chose the experiment shape. They came from scratch files,
not from this directory, and cannot satisfy the exact-source gate.

## Promotion gates

The checked-in result supersedes the scratch observation only after:

1. the exact source archive, pre-run and post-run manifests, build flags, and
   final binary hashes agree on both hosts;
2. every fixed A/B and A/A process is retained with explicit status;
3. all valid processes pass affinity, call-count, datagram-count, payload, and
   checksum gates, and the sender/receiver CPU pair stays fixed across the
   schedule;
4. the no-GRO and UDP GRO controls pass independently;
5. linked-image inspection finds scalar `send`, partial-aware `sendmmsg`, and
   one `sendmsg` path for `UDP_SEGMENT`;
6. the host record captures the loopback boundary and does not promote default
   interface capabilities into path evidence;
7. the receipt validator passes before and after the evidence hash manifest is
   sealed.

## Exact-source outcome

Source commit `750e9ea8729063d118409f9f73537d76cb8ad392` passed every
promotion gate on both required hosts. `sendmmsg`/scalar was 0.92617
[0.91796, 0.93445] on Arm and 0.93385 [0.92971, 0.93800] on `xxl`.
`UDP_SEGMENT`/scalar was 0.95531 [0.93810, 0.97283] on Arm and 0.78461
[0.77940, 0.78985] on `xxl`. Both A/A intervals included one. Both UDP GRO
controls preserved 128 logical datagrams and returned four 32-segment control
messages.

The [Arm record](../measurements/750e9ea-arm.md), [`xxl`
record](../measurements/750e9ea-xxl.md), and [cross-host
comparison](../measurements/750e9ea-comparison.md) state the exact boundaries.
The difference between hosts remains unexplained by this design.

## Run locally

Run the model checks from the repository root:

```bash
cargo test -p nic-datapath-cost-model --lib
cargo test -p nic-datapath-cost-model --doc
```

The socket experiment requires Linux headers and Linux UDP socket options. Run
the remaining commands from the repository root on Linux:

```bash
cc -O3 -g -std=gnu11 -D_GNU_SOURCE -fno-lto \
  -fno-omit-frame-pointer -Wall -Wextra -Werror -pthread \
  topics/026-nic-datapath/experiment/udp_batch.c -o /tmp/udp-batch

/tmp/udp-batch scalar 10 2
/tmp/udp-batch sendmmsg 10 2
/tmp/udp-batch udp_segment 10 2
/tmp/udp-batch udp_segment 1 0 --gro
```

Run the fixed schedule into scratch space:

```bash
python3 topics/026-nic-datapath/experiment/run_processes.py \
  --binary /tmp/udp-batch \
  --output-dir /tmp/topic26-processes
```

Run and validate an exact-source host bundle:

```bash
bash topics/026-nic-datapath/experiment/run_host.sh \
  "$PWD" /tmp/topic26-host
python3 topics/026-nic-datapath/experiment/validate_receipts.py \
  --evidence-dir /tmp/topic26-host \
  --source-root "$PWD"
```

The host wrapper records its exact command and environment. Use a new output
directory for each attempt. Do not overwrite a failed or superseded bundle.

# Round 01: compare useful lifetimes

Eight 64-bit fields make a 64-byte row. Compare a borrowed row baseline with
eight columns and 16-row tiles, retaining every field. The workloads are a
narrow scan, all-field scan, and shuffled whole-row read. Input sizes are
31, 4096 and 1048576. The all-field loop order follows each representation,
so this is a layout-plus-traversal comparison, not pure mechanism isolation.

For Q reads, conversion is worthwhile only when
`Q * (old_query_time - new_query_time) > conversion + teardown + reverse_conversion`.
Use a larger right side for extra mutation maintenance. Costs are an accounting
model, not additive cycle predictions. No reverse conversion is needed here.

Logical payload is 64*n for rows and columns, or 1024*ceil(n/16) for tiles.
Source rows remain alive during conversion. At n=1048576 this is 128 MiB of
source-plus-destination fields, plus 16 MiB of two visit lists on 64-bit targets.
Allocator overhead and excess capacity are additional.

Correctness uses a u128 element-wise oracle modulo 2^64, every-field round trips,
empty/tail/exact-multiple/overflow cases and poisoned tile padding. No unsafe
code, floating-point reassociation, mutation or concurrent reader protocol is tested.

# Round 1: One valid WAL prefix and one shared barrier

Date: 2026-08-12

## Question

Can a deterministic frame model distinguish damaged committed history from a
discardable tail, and can a Linux process experiment show the narrow benefit
of sharing `fdatasync` calls without claiming to test power loss?

## Acceptance contract

The byte-state model must:

1. accept three complete, contiguous, checksummed records;
2. enumerate all 160 byte-prefix cuts and recover only complete frames;
3. reject all 159 single-bit faults when three records are required;
4. fail closed for damage inside required history;
5. discard damage after required LSN 2;
6. reject a sequence gap; and
7. produce the same digest after recovering the accepted prefix twice.

The external supervisor must stop a child with `SIGKILL` after record 2 is
written, synchronized, and acknowledged in three separate cases. The
supervisor records acknowledgements outside the child and requires recovery to
cover that witness. Recovering extra unacknowledged data is permitted.

## Performance comparison

Each host runs eight complete blocks. Four use `ABBA`; four use `BAAB`. Each
letter is a fresh process:

- A writes 128 records and calls `fdatasync` after every record.
- B writes the same bytes and calls `fdatasync` after each group of eight.

The paired point estimate is the exponential of the mean block log-ratio
`log(B) - log(A)`. Dispersion is the sample standard deviation of those eight
block contrasts. A paired Student-t interval may be reported as an exploratory
description of within-window process and block variation. Inner records are
not treated as independent samples.

## Controls

- Both treatments write 128 records, 256 payload bytes per record, and the same
  total log bytes.
- A declares 128 syncs; B declares 16. The post-run validator recomputes these
  fields and all block contrasts from raw CSV rows.
- Each block has two A and two B observations.
- ABBA and BAAB occur equally often.
- Process start through exit, setup, and recovery remain outside the timed I/O
  region and are retained in separate columns.
- The WAL directory must be on the recorded XFS mount, not `/tmp` when `/tmp`
  is `tmpfs`.
- Generic and native builds both pass the model and process-crash workload.
- The native binary retains the `topic33_crc32c` symbol and its disassembly.
- Each host builds from the same clean Git archive and seals every receipt with
  Secure Hash Algorithm 256-bit (SHA-256) digests.

## Evidence boundary

- **Measured:** elapsed writes plus `fdatasync`, fresh-process duration,
  recovery duration, raw bytes, declared sync count, and within-window block
  variation for each exact host and run.
- **Observed:** process output, `SIGKILL` recovery, host identity, storage mount,
  toolchains, target features, binary symbols, and generated instructions.
- **Derived:** B/A geometric ratio, block-log-ratio dispersion, and an optional
  paired-t interval computed from eight complete block contrasts.
- **Source-backed:** Linux and PostgreSQL durability mechanics cited in
  `references.md`.
- **Not tested:** physical power removal, controller capacitor behavior, real
  PostgreSQL transactions, concurrent group formation, database throughput,
  or durability on another host or device.

## Promotion gate

Commit the source candidate before retained measurement. Run that exact commit
on the literal Arm target and on the runtime-resolved `xxl` Secure Shell (SSH)
alias. Promote evidence only when both archives share one source archive hash,
the correctness and process-crash checks pass, all raw benchmark rows validate,
code generation is inspectable, source bytes remain unchanged, and all
workspace gates pass on both hosts.

# Round 1: expose one-location serialization and retry work

## Question

With eight pinned writers, how do a direct shared atomic addition, a
compare-and-swap retry loop, per-worker atomic shards, and batches of 256 differ
on the two required Linux hosts?

This round tests final-count correctness, steady-state elapsed time, retry
amplification, and linked code generation. It does not measure fairness,
production work between increments, or cache-line transfer events.

## Fixed comparison

- Source: one sealed Git archive from the first Topic 47 source commit.
- Build: `rustc -O` with `-C target-cpu=native`, one code-generation unit, fat
  link-time optimization, and debug symbols.
- Work: eight workers and a frozen per-worker logical-update count.
- Placement: workers on processors 0 through 7 and the coordinator on processor
  8 after proving that all nine are allowed, distinct physical cores, and in one
  socket and one non-uniform memory access node.
- Shared treatment: one `AtomicU64::fetch_add(Relaxed)` per event.
- Compare-and-swap (CAS) treatment: one successful
  `compare_exchange_weak(Relaxed, Relaxed)` plus every recorded failure per
  event.
- Striped treatment: one `fetch_add(Relaxed)` per event on a 128-byte-aligned,
  128-byte-stride per-worker counter.
- Batched treatment: local accumulation with one shared `fetch_add(Relaxed)` per
  256 events and one final partial flush.
- Timing: startup, warmup-and-reset, steady work, and teardown are separate. The
  primary metric uses only steady work.
- Replication: 12 complete four-process Williams-cycle blocks. One block is one
  replication. An independent A/A control sends byte-identical shared runs
  through labels A and B in complete ABBA and BAAB blocks.
- Stopping: schedule, seed, process counts, inputs, and timeouts are fixed before
  primary collection. Failed processes remain in the receipt and invalidate
  their block.

## Analysis

For each candidate and complete block, subtract the shared treatment's log time
per logical update from the candidate's log time. Exponentiating the mean block
contrast gives the paired geometric-mean candidate-to-shared ratio.

Report the complete-block count, log-contrast standard deviation, range, and a
predeclared interval over complete-block contrasts. The interval covers
process-to-process and temporal variation during one exact host run. It does not
cover other builds, processors, virtual-machine placements, or workloads.

CAS failures divided by successful logical updates report software retry
amplification. They are not coherence-event counts. Batched timing carries a
different live-visibility contract and is reported with its flush count and lag
bound.

## Acceptance contract

1. The source archive embeds the recorded commit and matches its SHA-256 digest.
2. The literal Arm target is AArch64. The `xxl` alias resolves at run time, and
   its backing host is x86-64.
3. The coordinator and workers are allowed, distinct physical cores in one
   socket and one memory node. The observed coherence-line size divides 128.
4. Library, example, documentation, formatting, lint, and benchmark-build gates
   pass from the sealed archive.
5. Every process validates inputs, processor placement, final counts, retry or
   flush arithmetic, and timing phase boundaries.
6. All primary and A/A attempts remain in the receipt. The runner never replaces
   or silently retries a failed attempt.
7. Source, runner, archive, and binary hashes remain unchanged during collection.
8. The linked image retains all four stable kernel names and records their
   addresses. Same-address aliases are valid when the optimizer merges identical
   shared and striped bodies. Disassembly records the exact atomic lowering for
   each host.
9. Timing, retry, and generated-code observations remain separate from inferred
   cache-coherence mechanisms.

## Controls

- Keep source, compiler flags, logical work, ordering, placement, and process
  count fixed across the primary treatments.
- Balance each treatment across every position and directed first-order
  transition with a Williams cycle.
- Use fresh processes. Threads and loop iterations are subsamples.
- Record each worker's processor before and after steady work.
- Keep the coordinator off the worker cores.
- Reset warmup state before the measured phase without making the coordinator
  acquire every striped line.
- Run byte-identical A/A paths through the same parser and labels.
- Retain stderr, timeouts, invalid records, source hashes, and binary hashes.

## Evidence boundary

The controlled treatments can establish exact-host timing and retry differences.
Assembly can establish the emitted operation. Neither establishes cache-line
handoff counts, an L1-to-L1 path, or processor-family behavior. Hardware counters
or cache-to-cache samples, when supported, remain separate model-specific
evidence.

# Round 1: Equal-future sharing

Date: 2026-08-14

## Question

Can one topology-controlled probe show that exact right-language merging changes
space and lookup cost differently on structured and opaque byte keys?

## Acceptance contract

Before timing, every retained host run must establish:

1. The flat trie and minimal deterministic acyclic finite-state acceptor (DAFSA)
   agree with an independent sorted-vector oracle.
2. The `bar`, `bat`, `car`, `cat` trie has nine states and eight arcs; its
   minimal DAFSA has four states and five arcs.
3. Construction rejects descending and duplicate keys.
4. Empty keys, zero bytes, `0xff`, prefix keys, terminal extensions, early
   misses, middle misses, and truncations follow the declared byte contract.
5. Exhaustive bounded small-alphabet dictionaries and queries produce the same
   membership result.
6. Every reachable minimized state has a unique canonical signature.
7. Both benchmark methods report stable corpus, query, result, state, arc, and
   topology-byte metadata.

Any disagreement invalidates the run. Retain the failed attempt, but do not
promote its timing.

## Treatment and analysis units

One fresh process selects one method and emits both data-set rows. The runner
uses 12 complete four-period `ABBA` or `BAAB` blocks, six of each template in a
fixed seed-shuffled order. It also runs four trie-versus-trie blocks to check
the scheduling and analysis path.

The process is the treatment application unit. One complete block contrast is
the analysis unit. Inner lookups are subsamples, not independent observations.
Processes still share the host, scheduler, caches, thermal conditions, and
neighboring work.

For an `ABBA` block, where `A` is the flat trie and `B` is the minimal DAFSA,
the log contrast is:

```text
d = ((log(B2) + log(B3)) - (log(A1) + log(A4))) / 2
```

For `BAAB`, `B` occupies periods one and four. The point estimate is
`exp(mean(d))` across 12 blocks. Its sample standard deviation describes
block-to-block variation during that run window. This order removes an
additive linear position trend under the declared model; it does not remove
nonlinear drift or shared-host interference.

## Controls

- Both graphs use the same state record, arc record, and linked lookup kernel.
- `shared` and `opaque` keep high and low residual-language repetition separate.
- Each query sequence contains 50% hits and 50% append-byte misses.
- Correctness also covers miss depths excluded from the primary timing cell.
- The runner freezes repetitions before it launches the treatment schedule.
- Every process uses the same pinned allowed processor, binary, data, queries,
  and repetition map within a block.
- Four same-method blocks remain separate from treatment estimates. They check
  plumbing and do not define a universal noise floor.
- Generic and native binaries both pass correctness. Timing uses one exact
  native binary per host.
- Exported non-inlined lookup code remains available for disassembly.
- Output directories are single-use, and every attempt remains retained.

## Timing boundary

The timed interval contains warmed membership calls and checksum accumulation.
It excludes process startup, key and query generation, trie construction,
minimization, validation, calibration, warmup, and output.

The result is steady-state elapsed time for one synthetic membership mix. It is
not build throughput, startup latency, mapped-file first touch, memory
bandwidth, or a production request distribution.

## Promotion gate

Commit and push the source candidate before retained measurement. Archive that
exact commit and run it on:

- `dev-dsk-ahrav-2b-7dc7bd93.us-west-2.amazon.com`; and
- the runtime-resolved `xxl` Secure Shell (SSH) alias after confirming that the
  target reports `x86_64`.

Promote results only when both hosts use one shared source archive, all
correctness and benchmark receipts validate, required linked-code inspection
succeeds, and every workspace gate passes. A later documentation-only commit
can add evidence only when it leaves the measured code unchanged.

## Evidence classification

- **Measured:** elapsed and external wall time, topology counts, checksums,
  process order, compiler and host metadata, hashes, and linked instructions.
- **Derived:** nanoseconds per lookup, log contrasts, geometric ratios, and
  within-window sample standard deviation.
- **Source-backed:** exact-state minimization and cited implementation behavior.
- **Inferred:** memory locality, cache, branch, prefetch, and page-fault effects
  unless separately observed.
- **Not tested:** payload outputs, production libraries, Unicode equivalence,
  mapped files, fuzzy traversal, mutable updates, or processor families.

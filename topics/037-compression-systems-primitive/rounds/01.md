# Round 1: Compression-unit economics

Date: 2026-08-16

## Question

How do fixed codec work, history reset, framing, and raw fallback change when
the same 1,024 records use independent 256-byte units instead of one
256-kibibyte batch? One kibibyte (KiB) is 1,024 bytes.

## Acceptance contract

Before timing, every promoted host run must establish:

1. Identity, the low-latency LZ4 codec, and Zstandard (zstd) round trips
   reproduce every input byte.
2. Structured and deterministic-random corpus checksums match across methods,
   unit shapes, builds, and both hosts.
3. The logical input remains 262,144 bytes in every treatment.
4. LZ4 raw blocks carry an explicit compressed-length field in stored-byte
   accounting; zstd frame bytes come from the library output.
5. The selection policy chooses the smaller codec or raw payload under the
   common 13-byte unit header, with checked capacity arithmetic.
6. Generic and native builds pass correctness before the native binary times.
7. Every process records encode and decode intervals separately and verifies
   output after timing.
8. Receipt validation rejects missing periods, duplicate periods, invalid
   order, checksum drift, incomplete blocks, or executable identity drift.

Any failure invalidates that run. Retain the attempt, but do not promote its
timing.

## Treatment and analysis units

One fresh process receives one corpus, unit shape, and codec cell. Each of 12
main blocks contains the complete two-corpus, two-shape, three-codec grid. The
seeded restricted schedule uses every ordering of the three codecs with both
shape orders exactly once, and uses each corpus order six times. Calibration
is frozen before this schedule begins.

The process is the treatment application unit. The order tuple is assigned to
a block, and one complete-block contrast is the analysis unit. Repeated codec
calls inside one process are subsamples. The two named hosts are convenient
cases, not a random sample of processor families or a fleet. Processes on one
host still share its scheduler, caches, thermal state, and neighboring work.

For a positive time-per-byte metric `t`, where `log` is the natural logarithm,
each block contributes:

```text
d_block = log(t_numerator / t_denominator)
ratio   = exp(mean(d_block))
```

The unit-shape ratio is `batch / independent`; a value below one means the
batch used less timed codec-path time per input byte. Codec ratios are `lz4 /
identity`, `zstd / identity`, and `zstd / lz4`; below one means the named
numerator used less timed codec-path time per input byte. The report includes
the sample standard deviation of the 12 log contrasts and a working-model,
marginal two-sided 95%
Student-t interval for their mean. That interval assumes independent,
approximately normal block log contrasts. The sequential blocks on one shared
host do not establish those assumptions, so the sample standard deviation and
raw block contrasts are primary. The transformed interval is descriptive; it
does not guarantee coverage for another run, simultaneous coverage across
cells, or a repository pass decision.

Four two-period identity-versus-identity blocks run separately for every
corpus and shape. For A/A, `d_block = log(t_label-B / t_label-A)` and the
reported ratio is `label-B / label-A`. Both labels run identity, so this is a
plumbing control for labels, order, execution, parsing, and analysis. Four
blocks do not calibrate a false-positive rate or define a noise floor.

The horizon is fixed at 12 complete main blocks. There is no result-driven
stopping and no retry: a failed or incomplete attempt remains retained and
makes the run incomplete. No minimum detectable effect, policy threshold, or
power claim is attached to this descriptive experiment. The schedule balances
position under its declared additive-drift model; it does not remove nonlinear
drift, carryover, or shared-host interference.

## Controls

- Both unit shapes receive byte-identical structured and random corpora.
- Structured and pseudorandom data contrast repeated structure with a control
  expected to resist these codecs. The unit-shape treatment still changes call
  count, framing, history reset, and fallback together; this experiment does
  not identify any one mechanism in isolation.
- Identity exposes raw-copy and per-call overhead without claiming a storage win.
- Raw fallback accounts for expansion instead of forcing a codec result.
- Every timed child uses one pinned allowed processor and one thread.
- Setup, allocation, corpus generation, calibration, and warmup remain outside
  steady-state encode and decode intervals.
- A separate no-work process control records startup in the same run window.
- Identity-versus-identity blocks check schedule and analysis plumbing; they do
  not define a universal noise floor.
- Exported wrapper symbols remain available for linked-code inspection.
- Output directories are single-use, and every attempt remains retained.

## Evidence classification

- **Measured:** sizes, elapsed and wall time, checksums, process order, host and
  toolchain metadata, hashes, dynamic libraries, and linked call sites.
- **Derived:** throughput, log contrasts, geometric ratios, sample dispersion,
  raw-fallback selection, and break-even calculations.
- **Source-backed:** format and application programming interface (API)
  behavior in `references.md`.
- **Inferred:** fixed-call, history-reset, cache, branch, and vector effects
  unless separately isolated.
- **Not tested:** production data, physical I/O, dictionaries, concurrent load,
  slow-request latency, energy, hostile-input handling, or processor families.

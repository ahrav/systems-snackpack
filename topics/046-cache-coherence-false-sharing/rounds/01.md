# Round 1: isolate atomic false sharing

## Question

When two pinned workers update distinct atomic counters, how much does moving
the counters from one measured 64-byte cache line to separate lines change
fixed-work elapsed time on the two required Linux hosts?

This round tests an exact layout intervention. It does not count coherence
messages or establish whether the Arm core used near or far atomics.

## Fixed comparison

- Source: one sealed Git archive from the first Topic 46 source commit.
- Build: Rust release mode with `-C target-cpu=native`.
- Work: two workers, 10,000,000 `AtomicU64::fetch_add(Relaxed)` operations per
  worker, and 20,000,000 checked updates per process.
- Placement: logical processors 0 and 1, after proving that both are allowed,
  occupy distinct physical cores, and remain in one package.
- Layout A: counters eight bytes apart in one 128-byte-aligned object.
- Layout B: counters 128 bytes apart in separate aligned slots.
- Timing: starts after affinity setup and the ready barrier; ends at the done
  barrier before joins and teardown.
- Replication: eight complete primary ABBA/BAAB blocks, or 32 fresh processes;
  four complete padded A/A blocks, or 16 fresh processes.
- Stopping: the schedule, seed `20260825`, counts, and timeout are fixed before
  timing. Failed attempts are retained, never retried, and invalidate a block.

## Analysis

For each four-process block, average the logarithms for both A positions and
subtract the average logarithms for both B positions. Exponentiating the mean
block contrast gives the geometric-mean packed-to-padded time ratio. Report the
block count, log-contrast standard deviation, range, and a deterministic 95%
percentile bootstrap over complete blocks.

The interval describes between-block variation in one host, binary, CPU pair,
and run window. It is not a confidence statement about all Arm or x86-64
processors. The padded A/A schedule tests the runner's labels and positions; it
is not a calibrated noise floor.

## Acceptance contract

1. The source archive embeds the recorded commit and matches its SHA-256 digest.
2. Both authorized hosts match their required labels, resolved hostnames, and
   architectures. `xxl` resolves at run time and must be x86-64.
3. Both selected processors are allowed, distinct physical cores in one
   package, and report 64-byte sysfs coherence lines.
4. Library, example, and documentation tests pass from the sealed archive.
5. Every process validates layout, affinity, final counts, and echoed inputs.
6. All 48 attempts per host remain valid; no block is retried or replaced.
7. Source, runner, and binary hashes remain unchanged during collection.
8. Generated code from the measured binary contains a locked read-modify-write
   on x86-64 or the exact observed AArch64 atomic lowering.
9. Timing and generated-code results are reported separately from inferred
   coherence mechanisms. Unsupported PMU events remain an explicit limitation.

## Controls

- Keep work, atomics, ordering, placement, build, and process count fixed; only
  layout changes in the primary contrast.
- Use both ABBA and BAAB blocks to balance first-order position and drift.
- Use fresh processes so one process invocation is the replication unit.
- Record beginning and ending processor identifiers for both workers.
- Inspect addresses and sizes at runtime instead of trusting type names.
- Retain the complete attempt stream, including stderr and timeouts.

## Evidence boundary

The layout intervention and timing can establish an exact-host,
atomic-read-modify-write false-sharing penalty. Assembly establishes the emitted
operation, not the cache transaction path. `perf c2c` memory events were absent
on both required virtual machines during the initial run, so this round does
not instantiate ownership-handoff counts in the cost model.

Final checked-source observations are recorded in the dated host and comparison
notes under [`../measurements/`](../measurements/).

## Retained result

Both source-bound host runs passed all 48 attempts, source and binary identity
checks, layout and affinity checks, and exact-binary code-generation checks.
The Arm packed-to-padded geometric-mean ratio was 2.9770 with a descriptive 95%
block-bootstrap interval of [2.8985, 3.0598]. The `xxl` ratio was 5.4294 with an
interval of [5.1962, 5.6523]. Padded A/A ratios were 1.00036 and 1.00720; both
descriptive intervals included one.

The Arm binary emitted `ldadd`; the x86-64 binary emitted `lock incq`. Both
hosts rejected `perf c2c record -e list` because memory events were unsupported.
The retained conclusion is layout-sensitive atomic contention on these exact
hosts, not a measured L1-to-L1 migration or ownership-handoff count.

# Round 1: localized data dependency versus barrier

## Question

What process-level elapsed-time ratio does a localized data dependency or a
post-check speculation barrier produce relative to an ordinary checked lookup?

## Fixed comparison

The three modes return the same architectural value for every tested index.
The host gate records their exact Linux instruction shapes before timing them.
Eight alternating `plain`-versus-`plain` A/A blocks screen for label and position
bias. Twenty-four three-process blocks balance every mode order and compare
`mask/plain` and `barrier/plain` within each block on one pinned logical CPU.

## Acceptance boundary

A host result is publishable only when correctness, checksum equivalence,
target-specific code generation, the A/A threshold, fixed schedule, summary
recomputation, required-file digests, and captured source identity all pass
their gates. The [2026-08-22 comparison](../measurements/2026-08-22-comparison.md)
records the first passing visit.

This result answers one performance question for one build, input,
placement, host, and run window. It does not test transient disclosure,
mitigation completeness, or an entire instruction-set architecture. A
production decision still needs a gadget review, a defined trust boundary,
current processor and kernel guidance, generated-code inspection, and workload
evidence.

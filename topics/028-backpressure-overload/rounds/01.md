# Round 1: One-key miss-wave overload control

Date: 2026-08-07

## Question

For one synchronized 64-caller miss wave with the same physical outcome prefix,
how does key-scoped coalescing plus an aggregate retry budget change physical
origin work and release-through-rendezvous time relative to independent
per-caller retries?

## Fixed system and treatments

Every fresh process uses one synthetic key, 64 callers, a 64-caller waiter cap,
four physical origin permits, at most three attempts per flight, and two retry
tokens after the first attempt. Calibration targets 200 microseconds for one
physical work loop on each host. The observed mean is recorded, but the
validator requires only a positive value; it does not impose a closeness
tolerance. Attempt outcomes are fixed as `transient, transient, success`.

- `A`, naive: every admitted caller creates an independent flight and owns two
  retry tokens.
- `B`, controlled: the first admitted caller leads one key-scoped flight; all
  other admitted callers wait for its result; the flight owns one aggregate
  two-token retry budget.
- A/A: both labels use controlled mode through the same assignment, runner,
  receipt, and analysis paths.

The experiment compares the composition, not isolated toggles. The controlled
path includes singleflight, the aggregate retry budget, the waiter cap, and the
origin permit pool.

## Units and fixed horizon

| Role | Unit |
| --- | --- |
| Logical subsample | One caller thread inside a period |
| Physical subsample | One origin-work attempt inside a flight |
| Experimental unit | One fresh `overload-probe` process |
| Assignment unit | One predeclared four-period block |
| Analysis unit | One complete four-period block contrast |
| Sampling boundary | One exact binary, host, CPU set, and run window |

Threads are created before the measured release. A start barrier releases the
wave; a decision barrier ensures every caller has made its join-or-shed decision
before a leader can complete; an end barrier fixes `burst_ns` after all callers
have settled and rendezvoused. The metric includes barrier release overhead and
is not exactly `max(settled_ns)`. Thread joins and receipt serialization occur
after that endpoint. `setup_ns` is recorded but excluded from the primary
metric.

The schedule is fixed before observation:

```text
main: ABBA ABBA BAAB BAAB BAAB ABBA ABBA BAAB
A/A:  ABBA BAAB BAAB ABBA
```

Seeds `28_082_026` and `28_082_027` identify the main and A/A schedules.
Every letter is one fresh process. Each host therefore runs 32 main and 16 A/A
periods after one calibration process. Two additional fresh-process semantic
controls then exercise waiter shedding (`N=128, W=64, Q=2`) and aggregate retry
exhaustion (`N=64, W=64, Q=1`); they do not enter the timing estimator.

## Exact count contract

For admitted callers `A = min(N, W)` and attempts per flight
`k = min(M, 1 + Q, 3)`:

```text
naive flights      = A
controlled flights = 1
origin attempts    = flights * k
retry attempts     = flights * (k - 1)
```

The default configuration has `A=64`, `k=3`, and no shedding. Each naive period
must contain 64 completions, 64 flights, 192 origin attempts, and 128 retries.
Each controlled period must contain 64 completions, one leader, 63 followers,
one flight, three origin attempts, and two retries. Origin activity must never
exceed four; admitted callers must never exceed 64.

These counts are deterministic acceptance criteria, not statistical outcomes.
A count mismatch fails the process and the retained run.

The waiter-saturation control must complete 64 callers, shed 64, and retain one
flight with three attempts. The retry-exhaustion control must propagate one
shared exhausted result to all 64 admitted callers after two transient attempts,
with no completion or shedding.

## Records and estimand

Each logical row retains caller identity, process and assignment identity, role,
flight identity, admission and settlement timestamps, terminal status, and
shared-result digest. Each physical row retains flight and attempt number,
retry-token charge and remaining tokens, permit-queue/start/end timestamps,
synthetic outcome, active count at start, and work checksum.

For main block `b`, let `mean_B_b` be the arithmetic mean `burst_ns` of its two
controlled periods and `mean_A_b` the corresponding naive mean. The block
contrast is:

```text
D_b = ln(mean_B_b / mean_A_b)
```

The primary estimate is `exp(mean(D_b))`, the geometric controlled/naive burst-
time ratio across eight blocks. The two-sided 95% interval is a Student-t
interval on the eight log contrasts (`df=7`) transformed back to a ratio.
Periods receive equal weight. Caller and attempt rows are dependent receipts,
not independent replicates.

The interval describes block-to-block variation inside one host run window. It
does not cover host-day, source, workload, key, resolver, or fleet variation.
The four A/A label-B/label-A ratios are a descriptive path-asymmetry diagnostic
without an inferential interval.

## Measured versus inferred

- Raw timestamps, status rows, burst time, setup time, and active-count receipts
  are measured by the process.
- Counts, hashes, cap checks, and block contrasts are recomputed and validated
  from those receipts.
- The one-sixty-fourth physical-attempt count, a `64:1` reduction factor,
  follows exactly from this outcome prefix and count model.
- Production latency, DNS success rate, capacity, recovery, and multi-key
  behavior are not inferred from this run.

## Failure and no-replacement rule

Retain every calibration and period attempt with its command, timing,
stdout/stderr, timeout state, and exit status. A timeout, nonzero exit, missing
row, wrong assignment, count or checksum mismatch, timestamp violation, binary
or settings hash change, or incomplete block invalidates the whole run. Do not
replace a failed period after observing its outcome. A retry gets a new run
identity and repeats all 48 scheduled periods and both semantic controls; a
source correction requires a new commit.

## Scope boundary

This round does not implement real DNS, networking, a resolver, TTL or negative
caching, transport fallback, probabilistic failures, deadlines, cancellation,
backoff or jitter, recovery timing, multiple keys, global active-key admission,
tenant fairness, or fleet-wide retry budgets.

Deterministic backoff is specifically excluded because synchronized callers
would remain phase-aligned after the same delay. Randomized jitter is the
production mechanism used to spread retries, but adding it would create a new
treatment and confound the focused coalescing/count comparison.

## Promotion gate

Commit the candidate before measurement. Run the same commit and schedule on
the required literal Arm endpoint and on runtime alias `xxl`, recording its
resolved hostname. Promote results only after source, binary, final-image,
schedule, raw receipt, analysis, clean-tree, and evidence-manifest validation
passes independently on both hosts. Until then, local output is a harness check,
not an exact-candidate performance result.

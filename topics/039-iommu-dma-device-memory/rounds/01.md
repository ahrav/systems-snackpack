# Round 1: Keep device reachability separate from ownership

Date: 2026-08-18

## Question

Can a small executable model catch the address, direction, generation,
ownership, completion, and scatter/gather mistakes that an IOMMU alone cannot?

This round does not perform DMA, program an IOMMU, pin pages, maintain caches,
access a device register, or measure device or translation performance.

## Acceptance contract

Each required Linux host must:

1. verify a Git-created source archive against its full commit identity and
   Secure Hash Algorithm 256-bit (SHA-256) digest;
2. record the SSH target label, resolved hostname, architecture, kernel, CPU
   model and available count, page size, compiler and Rust toolchains, target
   features, build flags, visible IOMMU state, and relevant kernel config;
3. confirm that `xxl` resolves at run time to an x86-64 host and that the
   literal Arm target reports AArch64;
4. pass the crate's tests and deterministic probe;
5. run eight generic and eight native fresh-process probe replicas with no
   retry, requiring byte-identical expected output;
6. retain linked disassembly for the checked translation and DMA-mask hooks;
7. prove that the extracted source manifest is unchanged after execution; and
8. produce a manifest over every retained receipt.

One probe process is one replication unit. There are no inner timing samples.
The two build flavors check portability and code generation; they are not
performance treatments.

## Expected state changes

The probe begins with CPU ownership. It maps a contiguous 16 KiB IOVA aperture
over four noncontiguous 4 KiB physical pages, submits descriptor 41, and then
checks:

- a valid device write translates to the expected physical page and offset;
- a range beyond the half-open aperture is rejected;
- an intentionally wrong offset inside the aperture still translates;
- a direction mismatch and stale mapping epoch are rejected;
- CPU access and early unmap fail while the device owns the payload;
- an unrelated completion token fails and comes back to the caller, so its
  own mapping still completes;
- the matching completion returns CPU ownership; and
- unmap rejects the merged hardware count and accepts the original
  scatter/gather count.

The in-aperture success is deliberate. It demonstrates that address isolation
cannot validate the payload protocol.

## Evidence boundary

- **Measured:** process exit status, exact stdout, source and executable
  identity, host metadata, visible sysfs and kernel-config state, and linked
  generated code.
- **Source-backed:** Linux DMA API, IOMMU, SWIOTLB, Virtual Function I/O (VFIO),
  IOMMU file descriptor (IOMMUFD), page-pinning,
  shared-virtual-addressing, and device-I/O contracts in `references.md`.
- **Inferred:** how real devices would respond to address, translation-cache,
  cache-maintenance, reset, or fault behavior.
- **Not tested:** device DMA, IOMMU map or invalidation latency, I/O translation
  lookaside buffer misses, ATS caches, PRI faults, SWIOTLB copies, VFIO
  containment, MMIO ordering, device-local memory, or peer-to-peer bandwidth.

No elapsed-time comparison is justified. Both treatments execute the same tiny
CPU model, and no comparable authorized device path is available. Timing it
would not answer the topic's performance question.

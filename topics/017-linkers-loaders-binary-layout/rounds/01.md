# Round 1: binding moves latency

## Decision rule

Use identical ELF bytes to measure lazy versus eager binding. Use separately
linked images to inspect deployed layout and protection state.

This separation matters because `-z now` can change dynamic flags, GOT
placement, RELRO coverage, and addresses. `LD_BIND_NOW=1` moves PLT resolution
to startup without changing the file.

## Cost model

Pre-main work includes mapping and faults, relative relocations, symbol lookups,
relocation writes, page protection, and constructors. Lazy binding defers each
used PLT lookup and GOT patch to first call. It can avoid lookups for unused
imports.

The model predicts latency placement, not a universal total-time result.
Lookup scope, symbol versions, IFUNC resolvers, auditing, page state, and
constructors change the terms.

The measured `startup_ns` interval also includes child creation and exit.

## Evidence limits

- Eager binding does not remove the resolved PLT call path.
- The `noplt` fixture changes the external-call sequence and linked image.
- Full RELRO is a segment and protection result, not a flag-only claim.
- `DT_RELR` compresses relative-relocation metadata; it does not remove target
  writes.
- A steady-state difference needs a diagnosed mechanism before attribution.
- One host does not represent an ISA or vendor family.

## Result

On both measured hosts, eager binding increased the parent-observed startup
interval and reduced the in-process first-use interval. The exact estimates,
controls, and run boundaries are in the [cross-host measurement
note](../measurements/2026-07-27-linux-cross-host.md). Resolved steady
differences remain unexplained and support no mechanism claim.

# Round 1: Separate address bits, access permission, and compiler assumptions

Date: 2026-08-21

## Question

Can one defined-behavior experiment make three boundaries visible: numerical
address manipulation, Rust's source-level alias contracts, and the alias
assumptions recorded in generated code?

The example changes one array element with Strict Provenance, reconstructs one
exposed address for comparison without dereferencing it, and contrasts a
distinct-reference contract with a raw-pointer contract that permits exact
overlap. No test constructs overlapping Rust references.

## Acceptance contract

Each required Linux host must:

1. verify a Git-created archive against its embedded commit identity and Secure
   Hash Algorithm 256-bit (SHA-256) digest;
2. consume the locally recorded run-time resolution of the Secure Shell (SSH)
   alias `xxl`, confirm that the executing fully qualified hostname matches
   that resolved value, and require the target labeled `xxl` to report 64-bit
   x86 (`x86_64`); the fixed Arm target must match its literal hostname and
   report `aarch64` or `arm64`;
3. record the kernel, central processing unit (CPU) identity and available
   count, rustc and LLVM versions, Cargo, Python, binutils, target features, and
   the exact native build flags;
4. pass the seven full-workspace formatting, test, lint, benchmark-build, and
   documentation gates from the repository root;
5. build the example with release optimization, native CPU selection, and
   abort-on-panic code generation;
6. launch exactly eight fresh correctness processes without retry, requiring
   byte-identical expected standard output, empty standard error, and an
   unchanged executable digest before each launch;
7. retain optimized LLVM intermediate representation (IR), assembly, object
   code, linked symbol and executable metadata, and final disassembly;
8. require two LLVM `noalias` parameter attributes and one source load for the
   reference contract, no `noalias` parameter and two source loads around the
   store for the raw-pointer contract;
9. prove that the extracted source manifest is unchanged after the run; and
10. pass the independent receipt validator and retain a digest manifest for the
    evidence bundle.

One independently launched program is one replication unit. There are eight
correctness replications per host and no inner timing samples. The assembly and
linked disassembly are retained observations; the validator does not require
architecture-specific instruction mnemonics.

## Expected observations

Every process must print that the Strict Provenance write changes the third
array value from 30 to 99, the exposed pointer has the same numerical address
and is not dereferenced, distinct reference and raw calls return 14 and store
8, and the exactly overlapping raw call returns 15 and leaves value 8.

The optimized LLVM IR must expose the contract difference. The reference
parameters carry the observed non-aliasing attributes, and the retained body
uses one source load for both additions. The raw parameters carry no such
promise in the retained body, which uses a second source load after the
destination store to preserve the exact-overlap result.

## Evidence boundary

- **Executed and observed:** exact output from eight fresh processes per host;
  source, archive, runner, executable, and receipt digests; host and toolchain
  identity; LLVM IR attributes and load/store order; assembly, object, linked
  symbols, executable metadata, and final disassembly.
- **Source-backed:** the Rust pointer, reference, Strict Provenance, Exposed
  Provenance, `UnsafeCell`, and raw-pointer contracts in `references.md`.
- **Inferred:** the optimizer may reuse the reference function's first load
  because a valid call cannot overlap its arguments. The recorded LLVM IR is
  direct evidence of the selected compiler's assumption; the explanation links
  that observation to the source contract.
- **Not tested:** arbitrary unsafe code, dereferencing a recovered exposed
  pointer, every Rust compiler or type, a final Rust alias specification,
  elapsed-time performance, or instruction-set-family behavior.

No performance measurement is justified. The experiment tests semantic
permission and generated-code contracts. Its program is constant-size and its
runtime would mostly measure startup; timing undefined behavior would be
meaningless.

## Controls

The in-bounds Strict Provenance access is the positive pointer control. The
comparison-only exposed reconstruction prevents numerical equality from being
misreported as dereference validity. Distinct inputs make the reference call
valid. Exact overlap is executed only through the raw contract that explicitly
permits it. The separate LLVM bodies show that these exact builds use the
second load for the overlap-permitting case.

Run Miri as an optional additional control under its Strict Provenance mode.
Its success checks only the executed path under that version and model; it is
not part of the two-host completion gate.

# Arm correctness and generated-code observation

## Question and boundary

This run asks whether one exact committed Rust program preserves its defined
Strict Provenance, reference, and raw-pointer results on the required Arm host,
and which alias attributes and memory operations the selected compiler emits.
It reports no elapsed time. Eight processes replicate deterministic
correctness, not performance.

## Evidence boundary

The source identity, process results, host metadata, LLVM attributes, memory-
operation order, native instructions, and digests are observed. The reference
contract permits this compiler to reuse the first load; that link is an
inference supported by Rust and LLVM documentation. The result does not prove
all unsafe code, all rustc versions, an Arm-family rule, or a speed difference.

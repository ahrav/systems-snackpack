# Round 1: Reject invalid percentile aggregation

Date: 2026-08-23

## Question

Can one deterministic example distinguish a valid distribution merge from
averaged shard percentiles, unequal bucket schemas, and reset cumulative
counters?

## Acceptance contract

Each required Linux host must:

1. execute source extracted from one Secure Hash Algorithm 256-bit (SHA-256)
   digest-checked Git archive with an embedded full commit identity;
2. record the Secure Shell (SSH) target label and its runtime-resolved hostname,
   require `xxl` to report `x86_64`, and require the fixed Arm host to report
   `aarch64` or `arm64`;
3. record kernel, central processing unit (CPU) model and available count, Rust
   compiler and LLVM versions, Cargo, GNU Compiler Collection (GCC), Clang
   availability, target configuration, features, and native build flags;
4. pass the package tests and release build from the archived workspace;
5. run exactly eight fresh processes without retry, require byte-identical
   expected output and empty standard error, and check that the executable
   digest stays fixed;
6. retain optimized LLVM intermediate representation (IR), assembly, object
   code, linked symbols, and linked disassembly;
7. retain `topic44_checked_merge_four` in the linked binary; and
8. prove the extracted source manifest is unchanged and pass the independent
   receipt validator.

One process is one replication unit. Inner operations are not independent
samples. No timing interval is reported because this is a fixed-size semantic
check, not a throughput or latency benchmark.

## Expected observations

Shard A reports p99 of 1 microsecond, shard B reports 1,000 microseconds, and the
exact 1,010-observation union reports 100 microseconds. The unweighted average
of local p99 values reports 500.5 microseconds; the request-count-weighted
average reports about 10.891 microseconds. Both differ from the union.

An equal-schema count merge preserves all 1,010 observations and brackets p99
inside `(10, 100]` microseconds. A boundary mismatch and a decreasing
cumulative bucket counter must both produce explicit rejection.

## Controls and evidence boundary

- **Executed and observed:** deterministic output, eight fresh processes per
  host, source and executable digests, host and toolchain identity, tests,
  native build, LLVM IR, assembly, object code, linked symbols, and disassembly.
- **Source-backed:** percentile non-aggregatability, Prometheus bucket merge
  rules, OpenTelemetry aggregation temporality, HdrHistogram compatibility,
  DDSketch relative error, and sketch rank-error definitions.
- **Inferred:** averaging fails because local order statistics discard the
  cross-shard ordering needed by the union; matching boundaries preserve bucket
  meaning, while unequal boundaries do not.
- **Not tested:** telemetry pipeline loss, coordinated omission, production
  workload representativeness, every histogram implementation, elapsed-time
  performance, or an instruction-set-family code-generation rule.

The exact sorted union is the positive oracle, the independently computed
answer that a valid aggregation must match. An equal-schema histogram is the
lossy but mergeable control. Unequal schemas and a counter reset are negative
controls that must be rejected. The same source and expected output on both
hosts separate semantic agreement from host-specific code generation.
